## ✨ 这是什么

一套给**不懂代码的产品经理 / 学生**的开箱工具包。把它交给一个能操作你电脑的编码 AI（Claude Code、Cursor、Codex 等），贴一句启动句，AI 就带你从"一个想法"走到"上线产品"——写代码、跑测试、做界面、部署上线，全由 AI 完成；你只做少量"必须本人才能做"的事。

## 🎯 它解决什么问题

| 你的处境 | 这个工具包给什么 |
| --- | --- |
| 有产品想法，但不会写代码 | AI 替你写全部代码，你只做业务判断 |
| 网上教程太技术、太碎片 | 内置三份技术手册，AI 按阶段自动读取 |
| 不知道"做到哪算好" | 每个阶段有明确闸门和证据包，你能自己核对 |
| 卡在云平台、密钥、备案 | 上线阶段有"照着点"清单，注册/认证/开权限都有引导 |

## 🚀 快速开始（约 1 分钟）

1. 把整个文件夹放到你电脑上（压缩包先解压，**不要改里面文件**）。
2. 用一个**能读写文件、执行命令的编码 AI 工具**打开这个文件夹（网页版纯聊天 AI 不行）。
3. 在对话框贴这句话：

   ```text
   请读取项目根目录的 AGENTS.md，按其中"启动流程"开始。
   ```

4. AI 会根据你的情况自动走流程（有没有 PRD、是不是接着上次做）。之后每一步 AI 都会告诉你"下一步做什么"；看不懂就说"用产品语言再说一遍"。

> 📖 完整操作手册见 [开始看这里.md](./开始看这里.md)。

## 🧭 六个阶段

| 阶段 | 内容 | 你要做的 | 通过条件 |
| --- | --- | --- | --- |
| 0 PRD 体检 | 检查 / 补全产品需求 | 回答问题（≤5 个/轮，可回"按推荐"） | 补全清单全部关闭 |
| 1 技术适配 | 定技术方案 | 确认理解对不对、有无多出费用/范围 | 决策台账无影响本阶段的待定项 |
| 2 后端 MVP | 核心能力 + 真实验证 | 提供 Key、给真实结果打分、照清单验收 | 证据包已交 + 闸门全"是" |
| 3 正式前端 | 界面 + 移动端 | 给视觉方向、看代表页、真机走一遍 | 同上 |
| 4 上线 | 部署到云 | 注册/认证、控制台照着点、验收 | 验收清单全过 |
| 5 收尾 | 整理 + 删密钥 | 删云密钥 | 状态文件记录完成 |

每个阶段结束，AI 必须交**证据包**（截图 + 可打开地址/照着点步骤 + 是否表）。是否表有"否"就不能说完成。

## 🔒 内置的强制底线

这套规则卡约束 AI，你可以放心：

- 🔑 密钥不进仓库、不进前端、不回显
- 💾 数据可恢复，重启不丢
- ✅ 真实模型验证，不拿 mock 结果冒充
- 💰 涉及花钱的云资源，先告知费用再动手
- 🔐 用户只能看自己的数据
- 🛡️ 错误不泄露技术堆栈

## 🛠 当前项目：WorkMate（v0.7 销售周报工作台）

本仓库当前正在开发 **WorkMate**——本地 AI 销售数据周报助手。已完成：后端 MVP（数字自动核对、内容审核、权限白名单、日志）、本地网页工作台、生成前数据检查与字段确认、A/B 金额口径、报告周/对比周、事实卡与依据回查，以及 v0.7 的结果解释与口径确认。

订单量按完整订单号去重，同时展示明细行数；没有完整订单号时，订单量和客单价显示“待确认”。当前产品需求见 [PRD v0.7](docs/PRD/PRD-v0.7.md)；真实模型和真实销售样表仍待最后验收。

### 启动方法

**方式一：本地网页（推荐）**

```bash
python3.12 -m venv .venv            # 首次
.venv/bin/pip install -r requirements.txt
cp .env.example .env               # 首次；默认本地 Ollama，开发期可设 WORKMATE_MODEL_PROVIDER=mock
.venv/bin/python -m workmate serve --port 8000   # 浏览器打开 http://127.0.0.1:8000
```

打开后，在“已有数据表”中选文件（或点“选择本地文件”上传），依次点“检查数据”、确认字段和金额口径、选择周次、生成周报。右侧查看结果；左侧“最近任务”可重新打开已保存的周报。手机浏览器中，最近任务入口位于顶部品牌栏下方。

**方式二：命令行**

```bash
.venv/bin/python -m workmate run --instruction "把 data/你的表.xlsx 做成销售周报"
# 如需覆盖已有成品文件，加 --force（原始数据文件永不覆盖）
```

> 写总结默认用本地 Ollama（免费、数据不出本机）。没装 Ollama 时，把 `.env` 里 `WORKMATE_MODEL_PROVIDER` 改成 `mock` 可先跑通。

### 验证方法

1. 把你的销售表（xlsx/csv，需含“销售额”列）放进 `data/`（目录外的文件会被拒绝）。
   网页上传会校验文件是否可读取；同名文件不会被覆盖，请先改名再上传。
2. 跑上面的 `run` 命令（程序会自动核对数字，不一致会报错拒绝交付）。
3. 打开 `outputs/<任务id>/`：查看 `report.md`、`charts/` 三张图、`data_summary.xlsx`。
4. 抽查总销售额等 2–3 个数字与原始表一致，确认原始表未被改动。
5. 日志在 `outputs/.workmate/app.log`（只记耗时/状态，不记你的数据明细）。

### 测试

```bash
.venv/bin/python -m pytest -q
node --check workmate/static/app.js
```

网页使用项目内的 HTML、CSS 与 JavaScript，无需单独安装前端依赖或执行构建命令。

## ❓ 常见问题

**要花钱吗？** 两处：模型 Key（按用量付费，AI 会帮你估）；上线云费用（上线前会估，创建前必须经你确认）。开发期可先不买 Key，AI 用模拟数据推进。

**必须企业认证吗？** 正式上线的默认方案需要云平台企业认证。没有的话，AI 先用临时方案上线并明确三条限制，认证办好后再切换。

**AI 说做完了，我怎么信？** 看证据包：截图 + 可打开的地址 + 是否表。有"否"就不算完成。

**可以中途换模型 / 换工具吗？** 可以。规则和进度都存在文件夹里（`docs/项目状态.md`），不依赖某个模型的内存。
