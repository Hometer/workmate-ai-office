## 1. 产品定位（一句话）

**WorkMate**：一个**本地优先**的 AI 办公助理。用户用一句话下任务（"把 sales.xlsx 做成销售周报"），它在**本地**读取表格、算指标、画图、写总结，交付一份可直接使用的成品报告，**数据默认不出你的电脑**。

## 3. P0 场景：通用销售数据周报（完整定义）

### 3.1 用户故事

> 我是销售/运营，每周要把后台导出的销售表整理成周报。以前要打开 Excel 手动算总销售额、环比、Top5 商品、渠道占比，再画图、写总结，每周花一两个小时。我希望一句话就能拿到成品：数字算好、图画好、总结写好，我核对一下就能发。

### 3.2 端到端链路（核心闭环）

```
用户一句话下任务 + 指定 xlsx/csv 文件
   → search_files 定位文件
   → read_file 读取表结构（返回表结构 + 摘要，不整表塞上下文）
   → 任务拆解（s05）：算指标 → 画图 → 写总结
   → 本地计算指标（pandas，确定性代码）
   → 本地画图（matplotlib，确定性代码）
   → 写总结（本地模型）
   → safety_check 审核（s04 钩子）
   → verify_metrics 核对数字（s17）
   → write_file 落盘成品（s03 权限确认）
   → 返回「成果清单 + 改动说明」
```

### 3.3 输入 / 输出 / 验收标准

**输入**：授权目录内的 xlsx/csv + 一句自然语言指令（说明要算什么、出什么成果）。

**输出（成品，一期）**：一个周报文件夹
- `report.md`：周报正文（结论 + 关键指标 + 解读）
- `charts/`：图表（趋势图、Top5 柱状图、渠道占比饼图）
- `data_summary.xlsx`：计算后的汇总表（**原始文件只读，永不改动**）
- 返回消息附"我做了什么 / 数字依据 / 需人工核对的点"

**验收标准（s17 判断依据）**：
1. 指标数字与原始数据**核对一致**（`verify_metrics` 自动核对，非模型自证）
2. 图表能正常打开、表达正确
3. 总结**不编造数据**、有结论、可读
4. 成品落盘成功，原始文件未被改动

### 3.4 指标定义清单（metric-definitions 知识目录）

| 指标 | 算法 | 依赖字段 |
|---|---|---|
| 总销售额 | sum(销售额列) | 销售额 |
| 订单量 | count(订单行) | 订单/流水号 |
| 客单价 | 总销售额 ÷ 订单量 | 上述两项 |
| 环比增长率 | (本周 − 上周) ÷ 上周 | 周维度销售额 |
| Top5 商品/客户/区域 | 按销售额降序取前 5 | 销售额 + 分类列 |
| 渠道占比 | 各渠道销售额 ÷ 总销售额 | 渠道列 + 销售额 |

### 3.5 图表清单（chart-rules 知识目录）

| 图 | 类型 | 表达 |
|---|---|---|
| 图 1 销售趋势 | 折线图 | 每日/每周销售额走势 |
| 图 2 Top5 商品 | 柱状图 | 前 5 商品销售额对比 |
| 图 3 渠道占比 | 饼图 | 各渠道销售额占比 |

### 3.6 报告结构（weekly-report-templates 知识目录）

`report.md` 固定结构：**本周核心结论（一句话）→ 关键数字（总销售额、环比、客单价）→ Top5 表现 → 渠道表现 → 一条建议/风险提示**。总结 200 字左右，先结论后数据。

## 7. 架构设计（Step 4）

### 7.1 分层架构图（7 层 + 数据流）

```mermaid

    L1[① 交互层<br/>CLI 先行 → 本地网页 UI · 同步为主] --> L2
    L2[② 产品层<br/>会话管理 · 任务进度 · 成果展示 · 历史记录] --> L3
    L3[③ Agent 编排层<br/>loop s01 + 工具 s02 + 权限 s03 + 钩子 s04 + 任务 s05 + 技能 s07 + 目标闭环 s17 + 集成 s15] --> L4
    L4[④ 模型层<br/>默认本地开源模型 Ollama+qwen(理解指令/写总结) · 预留云端切换 .env · fallback] --> L3
    L3 --> L5
    L5[⑤ 能力集成层<br/>文件读写 · pandas 计算 · matplotlib 画图 · 内容审核 · 周报知识库] --> L6
    L6[⑥ 数据层<br/>会话历史 · 任务状态 · 用户偏好 · 轨迹数据 · 日志指标]
    L7[⑦ 基础设施层<br/>MVP 单进程 → 本地服务 · 沙箱 · 监控]
    L5 -.->|部署于| L7
    L6 -.->|部署于| L7

    subgraph 横切关注点
        SEC[安全边界：目录白名单 · 覆盖确认 · 数据不出本机 · 内容审核]
        OBS[可观测性：日志 · 每步耗时 · 数字核对结果 · 采纳率]

```

**数据流说明**：用户下指令 → ①传入 → ②建会话 → ③loop 经 s05 拆解为"算/画/写" → 调 `search_files`/`read_file` 读 xlsx（④理解表结构与指令）→ 本地 `compute_metrics` 算指标 → 本地 `plot_chart` 画图 → 注入 s07 知识调本地模型写总结 → s04 钩子触发 `safety_check` → s17 `verify_metrics` 核对数字 → `write_file` 落盘（s03 确认）→ ②展示成品 + 改动说明 → ①返回用户；全程日志/轨迹写入 ⑥。

### 7.2 工具清单

| 工具 | 输入 | 输出 | 副作用 | 权限 | 归属层 |
|---|---|---|---|---|---|
| `search_files` | 关键词/目录 | 匹配文件清单 | 无 | allow（仅授权目录） | ⑤ |
| `read_file` | 文件路径 | 表结构 + 数据摘要 | 无 | allow（仅授权目录） | ⑤ |
| `compute_metrics` | 指标名 + 数据 | 计算结果（数字 + 依据） | 无 | allow（本地） | ⑤ |
| `plot_chart` | 数据 + 图表类型 | 图片文件路径 | 写图 | allow（落临时区） | ⑤ |
| `write_file` | 路径 + 内容 | 写入确认 | 写文件 | ask（成品目录白名单） | ⑤ |
| `safety_check` | 生成文本 | 通过/拦截/需修改 + 理由 | 无 | allow | ③（钩子） |
| `verify_metrics` | 计算结果 + 原始数据 | 核对通过/不一致清单 | 无 | allow | ③（s17） |

> 实现说明：`compute_metrics`、`plot_chart` 本质是**本地沙箱里跑确定性 Python 代码**（pandas / matplotlib），不让模型心算，从根上避免数字幻觉。

### 7.3 系统提示词草案（销售数据周报专家）

```
你是「WorkMate」的数据周报助手，职责是：把用户指定表格，做成一份可以直接发出去的销售数据周报，并说明你做了什么。

规则：
1. 数字必须来自真实数据，绝不编造。所有计算交给 compute_metrics 工具（本地算），你只负责：理解指令、决定算什么、组织结果、写总结。
2. 先想后做：接到任务先列步骤（算哪些指标 → 画哪些图 → 写什么总结），再逐步执行。
3. 只读不动原始文件：原始 xlsx 一律只读；成品写到独立的成果目录。
4. 总结要短、有结论：先给结论，再给关键数字（总销售额、环比、客单价），最后给一句建议或风险提示。
5. 诚实：表里没有的数据、算不出来的指标，明确写"本表无此数据"，不要硬凑。
6. 交付前必须过 safety_check 和 verify_metrics，核对不过就修正，修正后仍不过就交还用户并说明卡点。

工具：search_files、read_file、compute_metrics、plot_chart、write_file、safety_check、verify_metrics
知识目录：weekly-report-templates（周报范式）、metric-definitions（指标算法定义）、chart-rules（图表规范）
```

### 7.4 模型层设计（本轮决策 C 的落地）

- **默认**：本地开源模型（Ollama + qwen 系），负责"理解指令 + 写总结"，数据完全不出本机。
- **预留切换**：模型层做抽象，`.env` 里配置提供商即可切到云端模型；界面须在切换时显式提示"将发送 XX 数据到云端"。
- **降级**：本地模型不可用/超时 → 返回已完成部分 + 卡点说明；若用户已授权云端，可回退云端完成"写总结"。

### 7.5 上下文与记忆策略

- **会话内**：`read_file` 只返回"表结构 + 数据摘要"，不整表塞上下文；需要明细按需再取。
- **跨会话（二期）**：s09 记住常用指标组合、成果目录、行文风格；MVP 用配置文件替代。

### 7.6 权限与安全边界 + 降级

- **目录白名单**：默认只读授权目录；成品只能写入指定成果目录。
- **原始文件保护**：原始 xlsx 只读、永不覆盖；写操作命中已有文件须 s03 二次确认。
- **数据不出本机**：解析、计算、画图全本地；只有"写总结"用模型，默认本地模型，切云端须显式选择并提示。
- **数字红线**：s17 `verify_metrics` 自动核对；不一致打回重算，杜绝编数字。
- **内容安全**：生成文本过 `safety_check`；不过审自动重写 ≤3 次，仍失败交付"保守模板 + 提示人工复核"。
- **解析失败**：文件打不开 / 表结构不清 → 明确告知，请用户确认"哪列是什么"，不瞎猜。
- **模型失败**：超时/报错 → 返回已完成部分 + 卡点说明，不假装成功。

### 7.7 可观测性

- 日志：每步耗时、工具调用、权限拦截、审核与核对结果。
- 指标：任务完成率、平均交付时长、**数字核对一致率**（核心质量指标）、用户采纳率。
- 轨迹：JSONL 记录（未来沉淀"销售周报范式库"与微调专用模型的原料）。

### 7.8 技术栈与部署形态

- **MVP**：单进程，复用本项目 `scaffold/agent.py` + s02/s03/s04/s05/s07/s15/s17；交互先 CLI，后加本地网页。
- **文件与计算**：`pandas` + `openpyxl`（读 xlsx/csv）+ `matplotlib`（画图）；计算画图全本地。
- **模型**：Ollama + qwen 系（本地默认）；`.env` 兼容云端提供商（预留切换）。
- **形态演进**：单进程 → 本地服务（网页 UI）→ 桌面壳（A 方向目标形态）。

## 11. 风险与应对

| 风险 | 应对 |
|---|---|
| 数字编造（最大风险） | 计算全走本地确定性代码 + s17 `verify_metrics` 自动核对，红线指标盯死 |
| 文件解析不稳（xlsx 结构五花八门） | read_file 先返回表结构让用户确认列含义；解析失败显式报错 |
| 本地模型能力弱于云端 | 写总结只做"短、有结论"的结构化文字，降低对文采的依赖；预留云端切换 |
| 安全事故（误删/越权） | 原始文件只读 + 目录白名单 + 覆盖确认 + 审计日志，M1 就上 |
| 场景太窄没人持续用 | 用"周报"高频刚需起步，靠采纳率决定扩场景 |
| 成本失控 | 上下文按需读、计算画图本地跑（零模型成本），只有写总结消耗 token |
| 被大厂碾压 | 不做全场景，本地优先 + 单点深 |
