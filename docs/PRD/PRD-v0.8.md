## 1. 目标用户与核心任务

### 1.1 一句话定义

用户把销售表导入本地工作台，确认统计口径，得到数字可回查、限制写清楚、方便交付的周报；下周处理同类表格时，可复用已保存的口径并重新检查数据。

目标用户继续为每周交销售周报的运营、销售、个体店主和小团队负责人。本版建议优先从现有用户范围中招募“每周用固定格式销售表向负责人汇报”的试用者，以便观察同一种任务的重复使用效果。该建议不改变已定目标用户或删除其他用户的现有功能。

### 1.2 用户价值与本版目标

- 信任结果：核心数字与用户确认的业务口径一致，每个总结结论有依据。
- 减少重复劳动：字段和金额口径可复用，新一周的数据仍重新检查。
- 完成交付：用户能将包含统计范围、单位、关键事实和限制的报告用于实际汇报。
- 独立使用：用户能知道本地模型是否可用，遇到问题能按提示恢复。

当前主要不确定性是实际销售表的兼容性、真实模型总结质量、用户修改量和本地启动难度。本版用真实验收获取这些证据，结果用于决定后续投入。

## 2. 输入、过程、产物与留存

| 项目 | 要求 |
| --- | --- |
| 业务输入 | 经授权的一张 xlsx/csv 销售表，沿用现有 20 MB 上传限制；原表只读。 |
| 人工确认 | 当前字段映射、每行金额或重复整单金额、货币单位、按周或全表统计；按周时确认本次两周覆盖情况。 |
| 验收输入 | 5—10 份经授权的真实业务样表及人工基准答案；特殊边界可另用合成数据补充回归，两类记录分开。 |
| 现有成果 | 网页结果、`report.md`、适用图表、`data_summary.xlsx`、`analysis_basis.json`，保留已有下载能力。 |
| 本版新增成果 | 真实验收与评分记录、启动诊断结果；阶段 B 增加本地口径预设及可复制周报。 |
| 本地留存 | 保存任务使用的数据版本、口径、确认记录、模型身份、降级状态和产物。新任务使用预设副本，历史任务保持原样。 |

真实样表、人工基准及含业务敏感值的评分记录存放在已忽略的本地运行目录，不进入 Git。对外交付的证据只使用经过授权与脱敏的材料；原始姓名、电话、订单号及完整文档不进入日志、模型输入或截图。

## 3. 用户主链路与人工确认点

### 3.1 首次使用

1. 打开本地工作台，查看启动自检，确认当前使用真实本地模型、演示模式或确定性降级摘要。
2. 导入销售表，系统检查数据并识别候选字段；用户核对字段、金额口径和单位。
3. 明确选择“按周生成”或“全表汇总”。选择全表汇总时保留日期字段识别结果，日期不作为周筛选条件。
4. 按周时选择报告周，查看紧邻前一自然周的记录覆盖并作本次确认；无记录或归属不明的对比周不产生比较结论。
5. 提交前再次确认数据版本。源表已变化时返回重新检查，不能沿用旧确认继续生成。
6. 查看结果和限制，回查事实，下载成果；阶段 B 可复制完整周报，或主动保存口径预设。

### 3.2 后续使用（阶段 B）

1. 导入新一周的同类表，主动选择已保存的口径预设。
2. 系统展示预设应用情况，重新检查当前文件。缺失字段、币种变化或其他冲突明确提示，不能自动放行。
3. 用户确认本次口径并重新选择周次、确认覆盖情况，生成一个新任务。

预设不代替本次检查、人工确认或数据完整性判断。复制周报只写入用户剪贴板，不自动向群聊、邮箱或外部系统发送。

## 4. 功能需求与验收标准

### F1｜真实样表和真实模型验收（P0，阶段 A）

- 收集 5—10 份真实样表，记录匿名样例编号、适用统计范围、金额含义、含税/退款规则、币种及人工基准。业务口径不明确的样例标“待确认”，不交给模型猜测。
- 样例尽量覆盖每行商品金额、重复整单金额、退款或负数、字段别名、无完整订单号、日期和对比周异常。真实样表未覆盖的边界由合成回归补充，覆盖缺口如实列出。
- 人工基准须独立核算，不直接复制系统计算结果。可用总额、行数、订单量、客单价、排名及比较结果按声明的显示精度一致；不可用项与原因正确。
- 实际运行约定的本地 Ollama + Qwen 模型，完成输入、检查、生成、持久化、查看和下载。记录模型名称/版本、运行环境、耗时、首轮结构合规、重试后合规和降级情况。
- 正常周报与全表汇总均覆盖真实模型完整链路；模型未运行、缺失或调用失败时标“待验/失败”，不能以 mock 或降级摘要证明真实模型质量通过。
- 真实模型不可连接、返回异常及超时的恢复行为须验证；适用边界在阶段开发文档中说明。真实调用与确定性故障回归分开记录。

**通过条件：**真实样例和模型链路已有可核对记录，硬性数字/隐私要求通过，产品经理完成第 5 节评分并冻结 D2/D3。已知不可接受问题修复后，用相关真实样例复验。

### F2｜检查与生成使用同一数据版本（P0，阶段 A）

- 检查时确定本次数据版本，并绑定当前字段、口径与确认信息。生成时后端必须验证实际计算输入与已确认版本一致。
- 数值、列名、日期或文件内容在检查后发生变化，即使文件名和列结构相同，也要求重新检查、重新确认，不生成带旧确认的报告。
- 任务计算、事实、图表、报告及依据文件使用同一份受控输入；生成过程中源表变化不能导致不同产物对应不同数据版本。
- 缺少有效确认信息的直接接口调用不得绕过校验。网页、CLI 及接口的兼容处理在开发文档中明确，不能静默造成旧调用方不兼容。
- 原始文件不修改，内部版本记录不把敏感原文写进日志；旧任务继续展示其当时的依据。

**通过条件：**检查后修改金额但不改列名、生成期间修改源文件等场景被正确处理；交付产物可追溯到实际输入版本，历史成果未被改写。

### F3｜总结结构、数字与事实引用校验（P0，阶段 A）

- 模型仅使用本次已核对且适用的事实，输出须通过结构校验。网页仍呈现普通业务语言，具体内部格式写入阶段开发文档。
- 每条实质性业务结论引用实际存在且可用的事实；引用存在但与结论不对应，也不能作为通过依据。
- 校验数字与对应指标、单位、范围和方向一致，覆盖小整数、金额、订单量、占比及负数；不能因数字小于 100 就忽略，也不能把出现在其他指标中的相同数字当作证据。
- 对“Top5”、日期或编号等非业务量值按其语义处理，避免误报。金额舍入和百分比转换沿用明确的显示精度规则。
- 总结不得增加数据无法支持的原因、预测、完整性判断，或不可用的环比；归因只能来自已有确定性计算支持的事实。
- 校验失败进行有限重试，最终仍不合格时交付确定性摘要并显式标注原因；保留有效数字成果，不能显示为真实模型质量通过。

**通过条件：**伪造小整数、引用不存在事实、引用错指标、颠倒涨跌方向及无依据归因均被拒绝或降级；合法事实及规范舍入可通过；真实样例通过 F1 的人工评分。

### F4｜成果口径与单位一致（P0，阶段 A）

- 网页、正文、图表轴或图注、汇总表、依据文件及阶段 B 的复制文本一致显示统计范围、金额单位及必要限制。
- 单位待确认时，各金额呈现处明确标注；单一 USD 等币种不得显示“元”；多币种继续阻断混算。
- “数字核对通过”“单位已确认”“用户确认周数据完整”“模型摘要通过”分别表达，计算一致不等同于业务数据完整。
- 文件即使脱离结果页，也能看懂按周或全表口径及单位。全表汇总不使用本周、上周或环比措辞。

**通过条件：**对元、USD、单位待确认、对比不可用及全表汇总逐项核对全部适用产物，结论和限制一致。

### F5｜本地启动自检与可操作恢复（P0，阶段 A）

- 检查本地模型服务能否连接、约定模型是否存在、授权数据目录与成果目录是否可用，显示“可用/需要处理”及具体下一步。
- 不可用时以“去哪、点什么或填什么、看到什么算对”的步骤说明；底层路径与错误仅在必要时显示，不回显秘密或堆栈。
- 演示模式、真实模型和降级摘要始终有明显区分。服务不可连接不能静默切为 mock；切换模式须用户主动操作并有清楚标识。
- 已生成任务、依据和下载不依赖模型此刻在线；模型恢复后可重新检查并创建新任务。
- 模型下载、安装和首次启动由执行者提供指导，本版不自动购买资源、不切云端。模型测试输入使用无敏感信息的材料，并注明用途。

**通过条件：**新启动、服务未启动、模型缺失、恢复连接及成果目录不可写均有正确提示；指定试用电脑完成实际启动验证。支持机型与耗时结论按实测记录。

### F6｜本地口径预设与业务语言（P1，阶段 B）

- 用户主动保存、命名和应用本地预设；保存字段映射、金额口径、人工声明单位及统计模式，不保存原始单元格、旧周次或旧完整性勾选。
- 预设来源于已确认的可用口径。应用后展示本次有效项和冲突项，重新检查；匹配失效时用户重新选择字段或改用手动确认。
- 页面主文案使用“每行商品金额相加”和“整单金额重复出现，按订单去重”，配简短示例；内部 A/B 标识可保留用于兼容。
- 明确提供“按周生成/全表汇总”选项；有日期也可选择全表汇总，不能要求用户清空正确日期字段来绕过流程。
- 预设持久化，更新预设不影响历史任务。覆盖同名预设须确认；保存冲突和损坏时提示恢复方法。

**通过条件：**下周同类表应用成功并重新检查；字段缺失、币种变化、预设冲突不能放行；重启可读取，旧任务和原表不变。

### F7｜可复制的完整周报（P1，阶段 B）

- 结果页提供“复制周报”，内容包含标题、统计范围、单位、适用关键事实、总结及重要限制，使用普通文本即可阅读。
- 降级摘要和单位待确认状态必须随复制内容保留；引用可读，不遗留内部调试字段；不复制隐藏的原始敏感信息。
- 成功显示复制成功；权限或浏览器限制导致失败时，提供可选中文本的手动复制方式。
- 保留既有下载。Word、PDF、PPT 等新增导出格式，根据 v0.9 用户实际交付方式另行排期。

**通过条件：**粘贴到文本编辑器后内容完整、口径一致；桌面及移动宽度可操作；复制失败有可用替代入口。

## 5. 什么算生成得好

### 5.1 硬性质量底线

- 数字与独立人工基准一致，统计范围和单位正确；归属不明或缺失的信息如实阻断/标注。
- 实质性总结结论有对应事实，不编造数值、引用、因果或预测。
- 原始文件不改，模型只接收允许的事实，历史和成果实际重启后可查。
- 产物能打开，限制跟随下载及复制内容；模拟、真实和降级状态明确。

以上任一项失败，不能用平均评分抵消。

### 5.2 产品经理样例评分

第一次真实冒烟后，执行者整理 5—10 条可直接阅读的真实结果，产品经理按四个维度打分，每项 1—3 分：结论正确、引用准确、依据易回查、表达适合交付。

1 分表示需明显修改或不能使用，2 分表示少量修改可用，3 分表示可直接使用；另标“不能接受”的样例与原因。根据评分冻结 D2/D3 的通过标准与瑕疵容忍度，未确认前继续记“待样例打分”，不预设通过率。

格式首轮合规、重试后合规、降级比例与内容评分分开统计。真实验收不能只展示挑选出的成功样例，样例总数及失败原因要完整记录。

### 5.3 使用效果观测

| 指标 | 记录方法与用途 |
| --- | --- |
| 交付耗时 | 从开始处理表格到用户认定可交付，区分首次安装耗时和日常任务耗时；与用户原流程比较。 |
| 人工修改量 | 记录需要改动的数字、口径、事实、表达与格式及修改耗时；不保存含敏感信息的原始修改内容。 |
| 下一周继续使用 | v0.9 记录 5 名种子用户的有效使用机会、是否继续用及未使用原因；连续观察 2—3 周，不将暂无周报任务记作流失。 |

本版先采集基线，具体速度目标、修改量目标和复用判断依据在真实验收后确定；5 人试用只用于发现问题，不据此推断市场规模或稳定留存率。

## 7. 模型、成本、数据与非功能约束

- 模型沿用本地 Ollama + Qwen 先行；准确型号、量化版本及运行参数在验收方案记录。默认数据不出本机，切云端需先脱敏并显式授权。
- 月度成本上限仍为 500 元；本版不创建付费云资源。本地模型无云 API 调用费，安装所需下载、硬件占用和实际耗时如实说明，不承诺未经验证的性能。
- 错误统一为 `{"error":{"code","message"}}`，模型调用处理初始化/连接失败、超时、有限重试和校验失败。任务状态及人工确认点持久化。
- 重要状态以现有本地存储持久化，兼容旧任务；服务重启后运行中任务可识别中断，成功/失败任务与成果可找回。自动从中间步骤续跑另行定义，不能用历史找回宣称已实现断点续跑。
- 上传格式、真实内容、大小、安全文件名和白名单要求继续有效；同名原表不覆盖，成果覆盖保留人工确认。
- 桌面与 390px 移动宽度验证错误、确认、复制和下载，避免页面级横向溢出；手机实机使用与本地可达性另行实测，不以缩小浏览器代替。
- 不新增遥测、自动收集真实样表或外部分析服务；使用效果按用户授权在本地记录。非本机访问与正式多用户上线不在本版范围。

## 8. 验收矩阵与交付要求

| 场景 | 预期结果 | 验证方式 |
| --- | --- | --- |
| 真实 A 周报、真实 B 适用样表、真实全表汇总 | 数字符合各自人工基准，实际模型完整链路和产物可核对 | 真实样例、真实本地模型、人工评分 |
| 检查后仅金额变化，或生成期间源表变化 | 不沿用失效确认；交付的全部产物与同一受控输入一致 | 合成回归、接口及浏览器实测 |
