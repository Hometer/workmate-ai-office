# PRD v0.5｜WorkMate 可信销售周报

> 日期：2026-09-28  
> 状态：产品方案待确认，尚未开发 v0.5 功能。  
> 版本关系：在 v0.4 的本地周报能力上增量优化。v0.4 保留作历史版本，已完成的 M3.1 复核修复以 `docs/项目状态.md` 为准。

## 1. 本版要解决的问题

WorkMate 当前已能在本地选择或上传 xlsx/csv，生成报告、可用时的趋势图、Top5 商品图与渠道图、汇总表，并保存任务历史。订单号去重、独立数字核对、输入校验、中断状态和失败提示已经实现；mock 自动测试为 49/49。真实 Ollama 和真实销售样表仍待验证。

下一步的主要风险是**数字看起来完整，但计算前提可能不对**：同一订单的整单金额若在商品明细中重复出现，逐行相加会高估销售额；最近两条有数据的周不一定是完整、连续的两周；用户也看不到某个结论到底来自哪一列、哪段时间。v0.5 先让用户确认口径，再计算和生成，并让报告中的事实可以回查。

**产品目标**：让每周交销售周报的运营、销售、个体店主和小团队负责人，在本地用一张表生成一份“口径明确、数字可信、可人工复核”的周报。仍为单机单用户、数据默认不出本机。

**成功场景**：用户上传一张后台导出表，看到检查结果，确认列与金额口径、选择报告周，随后获得带数据依据的周报；有缺失或歧义时知道哪些结论不能生成，而不是收到貌似完整的错误结论。

## 3. 用户、输入、流程与产物

### 3.1 目标用户和范围

- 用户与场景沿用 v0.4：每周整理通用销售数据的运营、销售、个体店主和小团队负责人。
- 输入仍为授权目录中的 xlsx/csv 或网页上传的 xlsx/csv；首期只处理一张逻辑数据表。不自动合并多文件、多工作表或跨平台账户数据。
- 单机单用户，不新增登录、多人协作、云同步或定时对外发送。月度成本上限仍为 500 元；本版不创建收费云资源。

### 3.2 主链路

1. **选表**：展示文件名、文件类型、行数、数据日期跨度；预览列名和少量脱敏样例。
2. **检查与确认**：展示销售额、日期、商品、渠道、订单号的自动匹配结果；用户可纠正列选择，并明确金额口径。界面列出阻断项与可继续的提醒。
3. **选报告周**：默认选文件内最近有数据的自然周，显示周一至周日的准确日期；前一自然周作为对比周。用户确认两周数据是否完整后才允许出现环比。
4. **生成**：本地计算、独立核对、画可用的图、使用本地模型写短总结；模型失败时保守降级并显式标注。
5. **复核与下载**：报告中的关键数字可查看计算依据；历史任务能重新打开当时的口径、报告和产物。

### 3.3 交付物与留存

- 继续交付 `report.md`、可计算的 `charts/` 图片、`data_summary.xlsx`。缺字段的图在界面与报告中说明“未生成原因”，不能以空图代替。
- 新增同目录的 `analysis_basis.json`，保存本次字段映射、金额口径、日期范围、过滤/排除计数、指标公式版本、独立核对结果和原始文件指纹。只在本机保存，不写客户姓名、电话等原始行值。
- 网页任务历史展示上述信息的易读摘要。原始文件只读；生成结果写入独立成果目录，按现有覆盖确认规则处理。
- 用户可返回检查页修正口径再生成，新结果使用新任务保存，旧任务不被悄悄改写。

## 4. 功能需求与业务规则

### F1｜生成前的数据检查与字段确认（P0）

| 项目 | 要求 |
| --- | --- |
| 字段映射 | 自动建议销售额、日期、商品、渠道、订单号列；用户可改，销售额必填。映射确认后才生成；有多个同名或相似列时不得擅自选定。 |
| 质量摘要 | 对**全表**统计数据行数、销售额非空/空/无法解析数、日期非空/空/无法解析数、订单号完整率和重复订单号数；界面说明“全表统计”，样例预览另标“仅预览”。 |
| 样例保护 | 样例默认只展示参与计算的字段；对姓名、电话、邮箱、地址等疑似个人信息列不显示原值。完整原始行不得写进日志或模型输入。 |
| 阻断与提醒 | 缺销售额列、金额为空或无法解析、空表、金额口径无法确定时阻断生成。日期为空或无法解析时可改走“全表销售汇总”，不得静默排除这些行后生成周报；缺商品/渠道列只影响相应图和结论。 |
| 无声排除 | 任何被排除的行都要有数量、原因和受影响指标；不允许把无效金额静默当 0 或悄悄删行。 |

### F2｜金额粒度与指标口径（P0）

**用户必须在首次生成前确认金额含义**，提供两种业务选项，默认不替用户做最终判断：

| 选择 | 适用表格 | 总销售额与分类统计 |
| --- | --- | --- |
| A 每行是该商品/明细的金额 | 一笔订单可有多行，每行金额各不相同或虽相同但确为独立明细 | 每行金额相加；商品、渠道、日趋势按对应行汇总 |
| B 同一订单的整单金额在多行重复 | 一笔订单的多条商品行都填同一个整单金额 | 每个订单号的金额只计一次；订单内金额不一致则阻断并提示；无法可靠分摊到多商品时，不生成商品金额排名 |

- B 必须有**每行完整订单号**。同一订单若跨多个日期或渠道且无法确定归属，相关日期趋势、周比较或渠道占比分别标“口径待确认”，不得把整单金额重复计入多个分类。单一日期/渠道且一致时可以按订单归属汇总。
- 订单量沿用 v0.4：完整订单号去重计数；无订单号或部分缺失时展示明细行数，订单量与客单价标“待确认”。A 模式下仍允许生成其他有依据的金额指标；B 模式下订单号不完整则阻断所有金额计算。
- 客单价 = 本次统计范围内的总销售额 ÷ 同范围内的去重订单量，分母为 0 或未知时不计算。不能把明细行数当订单量。
- 当同一订单号跨越多个报告周且无法确认统一订单日期时，该订单不能被准确归入某一周；对应周的订单量与客单价标“口径待确认”。
- “销售额”仅指用户选定列的原值汇总。负数按原表计入并提示数量；没有明确字段与规则时不擅自解释为净销售额、成交额或退款额，也不自行换汇。若发现同一统计范围内有多个币种，阻断跨币种总额和占比，提示先提供单一币种数据。
- 渠道占比只有在总额大于 0 且各渠道汇总额均不为负时才用饼图表达；否则展示各渠道金额表，并解释占比不可用，避免负数扇区或超过 100% 的误导图。
- 所有金额计算由确定性代码执行，继续用独立路径复核；模型不能决定去重、分摊或过滤规则。

### F3｜周范围与可比较性（P0）

- 周一 00:00 至下周一 00:00，按用户本机时区确定自然周；报告明确写起止日期和时区。报告周默认是数据中最近有记录的自然周，用户可选其他有记录的周。
- 对比周为报告周紧邻的前一自然周，不能跳过空白周去找更早的“上一条有数据的周”。只显示报告周总额时也标注该周覆盖的实际日期和有效记录数。
- 界面展示两个自然周各自有记录的天数、日期空值/错误数和是否落在源文件日期范围内。**有记录的天数少于 7 天并不能证明数据不完整；7 天都有记录也不能证明导出完整。** 用户须分别确认两周数据覆盖完整，确认记录保存在本次任务中。
- 两周都有可计算金额、日期可归属、口径一致且用户确认完整时，环比 =（报告周金额 − 前一周金额）÷ 前一周金额；前一周金额为 0 时只报两周金额与差额，不报百分比。任一条件不满足，报告写明“环比暂不可用”及具体原因，不使用含糊的“无数据”。
- 文件没有可用日期列时，产物标题改为“销售数据汇总”，不使用“本周”“环比”“趋势”字样；总额、订单量等仍按全表口径显示。
- 周报中的总销售额、明细行数、订单量、商品与渠道统计均只取报告周；对比周只用于比较和变化事实。检查页的“源文件总行数”和周报“报告周明细行数”分别命名，不得混写。选择“全表销售汇总”时，各指标才取整张表。

### F4｜有依据的结论与复核入口（P0）

- 先生成“事实卡”：报告周总额、订单量/客单价、可用的环比、Top5 商品、渠道占比；每张卡记录数据范围、源列、计算式、排除数、独立核对状态，展示适用的单位和精度。
- 若两周都完整且分类字段可靠，确定性计算最多 3 条变化事实，例如“渠道 A 比上周减少 X，约占总降幅 Y%”。分类维度不可用时不生成该类事实。正负贡献的分母与方向要在卡片中写明；不把相关变化写成因果。
- 贡献事实只在总变化不为 0、分类可完整覆盖该指标且正负方向一致时给出“占总增幅/降幅”；其他情况只列分类绝对变化，不给可能超过 100% 或方向相反而难懂的贡献百分比。
- 模型只根据已通过核对的事实卡写不超过 200 字的中文总结。每个含数字的结论关联卡片编号；没有可支持的事实则不生成“建议”。禁止凭空给出原因、销量、利润、增长率或运营动作效果。内容审核失败后保守降级，并显示“需人工复核”。
- 报告正文、网页、图表和汇总表使用同一份冻结的计算结果；修正口径后重新生成新的结果。下载的报告和汇总表能看见报告周、金额口径、是否完整及不可用指标原因。

### F5｜每周重复使用（P1，P0 验收后安排）

- 可在本机保存“表格口径预设”：按列结构指纹关联字段映射和金额粒度；下周同结构文件可自动带出供用户确认。**不复用**上周的数据完整性确认或报告周日期。
- 用户可删除预设；预设不含原始行、客户信息或密钥。旧文件/旧任务仍可按原口径查看。

## 5. 页面与异常状态

| 页面/状态 | 用户应看到什么 |
| --- | --- |
| 选择文件 | 支持的文件、上传结果和受控文件路径；上传格式/真实类型/大小/同名问题仍沿用 v0.4 规则 |
| 检查数据 | 文件摘要、字段映射、全表质量、A/B 金额选项、问题严重度和可操作的修正提示 |
| 选择周 | 报告周、前一周、各周覆盖情况与完整性确认；无日期时直接显示“销售汇总”路径 |
| 生成中/失败 | 明确任务状态与可理解的错误；服务中断后可重新生成，不出现永久转圈 |
| 结果 | 先看关键数字和口径提示，再看短结论、可用图表、依据卡与下载；mock/模型降级必须明显标识 |

桌面和 390px 移动宽度都需可用。时间选择、字段选择、完整性确认和“重新生成”均需键盘可操作；颜色之外仍有文字说明错误与提醒。

## 6. 范围、优先级与交付顺序

| 优先级 | 本版交付 | 完成判断 |
| --- | --- | --- |
| P0-1 | 数据检查、字段确认、A/B 金额口径 | 不确定或错误输入不会生成带错误金额的“成功”报告 |
| P0-2 | 明确报告周与比较周、完整性确认 | 不完整/不连续/无日期数据不出现误导性周环比 |
| P0-3 | 事实卡、出处、报告呈现与产物冻结 | 报告每个关键结论能回到同一任务的数字依据 |
| P1 | 本地口径预设 | 同结构新表能复用映射但必须重新确认当周完整性 |

本版不做：PPT、跨文件拼接、多工作表合并、自由问答、自动归因/预测、自动给别人发周报、多人登录、云端数据源或通用 BI 编辑器。若真实样表表明“整单金额重复”不是首批用户的常见情况，F2 的 B 仍作为防错能力保留，产品经理可在实施前调整交付顺序。

## 7. 验收标准

### 7.1 可重复的功能验收

1. **重复整单金额**：两条明细同属订单 A、各填整单 100，另一个订单 B 填 50。选 B 后总额为 150、订单量为 2、客单价为 75；A 的多商品金额排名标不可用。选 A 后总额为 250，并在报告中明示“每行金额相加”，不能暗中替用户改口径。
2. **B 的冲突与缺号**：同订单两行整单金额不一致，或任意一行无订单号，生成前阻断；错误说明涉及的行数与修正办法，不在日志打印原始行值。
3. **周比较**：文件有第 1 周和第 3 周数据、缺第 2 周时，选第 3 周的前一周必须是第 2 周；不自动拿第 1 周算环比。只有一周、任一周未确认完整、日期无法归属或前一周为 0 时，分别显示准确的不可用原因。
4. **无日期/缺分类**：无有效日期时标题是“销售数据汇总”；无商品或渠道时只缺对应图与结论，其他可计算指标照常生成。
5. **质量计数**：1,500 行数据的第 1,200 行有非法金额，检查页按全表报错并阻断，不得因为预览只显示前几行而漏掉。
6. **证据一致**：报告、网页、图表和汇总表的金额与同一 `analysis_basis.json` 口径一致；独立核对故意注入错误时任务失败；旧任务在新任务生成后仍能查看原口径。
7. **安全与恢复**：原始文件哈希不变；日志、模型输入和前端错误不含完整文档、客户信息、密钥或堆栈；运行中断后的任务可查询并能重试。

### 7.2 真实使用验收

- 用 5～10 份**经脱敏且获准使用的真实销售样表**覆盖 A/B 金额口径、有/无订单号、完整/不完整周、缺失字段和负数。产品经理逐份核对总额、订单量、周范围、图表和结论，并给总结可读性打分；据此关闭 D2/D3 的“待样例打分”。当前没有真实数据，此项如实标“待验”。
- 本地 Ollama 真正生成至少 1 份报告，检查模型输出、引用事实和失败降级。mock 测试不能替代真实模型冒烟；当前此项也为“待验”。
- P0 自动测试、类型/Lint/生产构建（适用时）、桌面与移动检查、重启恢复、密钥排除、README 和阶段证据包按 `AGENTS.md` 闸门交付。真实模型与真实样表未通过前，不宣布 v0.5 开发阶段完成。

## 8. 非功能、成本与隐私

- 保持本地优先、单机单用户。原始数据仅在授权目录读取；输出仅写成果目录；上传继续校验格式、真实类型、大小和安全文件名。
- 指标、口径选择、完整性确认、任务状态和结果持久化，重启后可查。接口继续约定请求/响应/统一 `{"error":{"code","message"}}`；模型超时、失败、有限重试和兜底沿用现有约束。
- 文件检查属于本地计算，界面显示进度和可取消状态；具体耗时上限待首批真实样表测量后确定，不在无数据时承诺性能数字。
- 日志仅保留任务 ID、状态、耗时、错误代码及必要的非敏感计数，不记录完整路径、完整指令、原始行或可推断客户身份的个人信息。云模型切换须另行确认脱敏与外发授权。
- 不创建收费资源；若以后为部署或云模型产生费用，仍遵守既有 ≤500 元/月预算与创建前确认。
