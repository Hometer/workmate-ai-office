# PRD v0.7｜WorkMate 可信计算与结果解释

> 日期：2026-09-29  
> 状态：产品审阅稿，待产品经理确认；不代表 v0.7 已开发或验收。  
> 版本关系：继承 v0.6 的目标用户、单机单用户、本地优先、A/B 金额口径、自然周、事实卡及隐私边界。本版处理 M3.4 后复核发现的计算与展示缺口；真实模型、真实样表打分安排在 v0.8，种子用户试用安排在 v0.9。

## 1. 一句话定义

用户导入一张销售表，确认字段、金额口径和货币单位后，即使上周没有数据或表格有字段歧义，也能得到一份口径清楚、数字可核对、不可用结论有原因的报告。

目标用户仍是每周要交销售周报的运营、销售、个体店主和小团队负责人。v0.7 不改变“一张 xlsx/csv → 本地销售周报”的产品形态。

## 2. 当前基线与本版目标

截至 2026-09-29，项目状态记录 M3.4 的 mock 自动测试 77/77 通过，已有导入、检查、选周、生成、历史找回及报告/图表/汇总表/依据文件的主链路。真实 Ollama 与真实销售样表仍待验；自动测试通过不等于产品验收完成。

本版要关闭以下已由代码路径发现、但尚未逐项用真实样表复现的风险：

| 编号 | 优先级 | 当前风险 | v0.7 要达到的结果 |
| --- | --- | --- | --- |
| V7-1 | P0 | 报告周有数据、紧邻前一周无记录时，对比周空表计算可能使整份任务失败。 | 交付报告周结果；环比、差额和变化归因均不生成，并说明“对比周无记录”。 |
| V7-2 | P0 | 用户改选字段后，页面仍沿用初次自动识别字段的质量统计和周信息。 | 质量计数、周范围、阻断原因与最终采用的字段映射一致。 |
| V7-3 | P0 | 无可靠币种列时直接把金额写成“元”。 | 单位由可靠字段或本次人工声明确定；未确定时明确标“单位待确认”。 |
| V7-4 | P0 | B 口径跨周归属不明时可能禁用环比，却仍生成跨周渠道变化事实。 | 同一条件统一约束所有跨周变化结论及“已核对”标识。 |

| V7-6 | P1 | 关键口径与不可用原因散落在页面、报告和依据文件中。 | 结果页先给用户一眼可读的“本次口径与限制”，并与下载产物一致。 |

## 3. 用户主链路

1. 选择或上传授权目录中的单张 xlsx/csv，系统识别候选字段并做全表检查。
2. 用户确认销售额、日期、订单号等字段，选择 A“每行金额”或 B“重复整单金额”；如币种无法可靠识别，确认单位或选择“单位待确认”。
3. 每次修改参与计算的字段，系统重新检查对应列，刷新质量计数、可选报告周与阻断原因；检查完成前不能沿用旧结果提交。
4. 用户选择有记录的报告周，看到紧邻前一自然周的记录覆盖情况。前一周无记录时仍能生成报告周结果，但不展示任何跨周比较结论。
5. 结果页先展示本次口径和限制，再展示事实卡、总结、图表、依据及下载入口。没有可靠日期或未选周时，用户走“全表销售数据汇总”。

## 4. 功能与业务规则

### F1｜空对比周不阻断报告周（P0）

- 报告周必须有可计算的记录；仅对比周无记录时，不将空表交给金额计算、独立核对、图表或模型总结流程。
- 报告周的总销售额、明细行数、可用订单量及图表继续正常计算和核对，任务可成功交付。对比周在页面、报告和依据文件中标为“无记录”，不把“无记录”冒充为“销售额 0”。
- 对比周无记录时不生成环比百分比、销售额差额或任何变化/贡献事实；解释为“紧邻前一自然周无记录，无法比较”，不跳到更早有数据的一周。
- 对比周有记录且金额确实为 0 时，可展示两周金额及差额，但不计算以 0 为分母的百分比；原因写明“对比周金额为 0”。
- 用户通过接口指定没有记录的报告周，应收到可读业务错误；不能返回一份标记成功的空周报。

### F2｜字段变更后重新检查（P0）

- 销售额、日期、订单号、商品或渠道映射发生变化后，页面上相关的有效/空/无法解析计数、订单号完整率、周列表、周覆盖、阻断原因与预览必须基于**当前映射**重新计算。未改变的原始文件信息可复用。
- 重新检查完成前，禁用生成入口；重新检查失败时保留用户已选字段，显示可操作错误，不退回旧统计或旧“可以继续”状态。
- 日期列变更时清空已选报告周、对比周及两周完整性确认。销售额或订单号列变更时重新判断 A/B 口径的可用条件；旧检查结果不得作为新映射的确认凭据。
- 后端在创建任务时校验映射列属于当前文件，并以当前文件及映射重新验证阻断项。若文件在检查后发生变化，要求重新检查并重新确认口径，不使用旧文件指纹继续生成。
- 预览仍只展示允许的业务列，不展示疑似个人信息的原始单元格。

### F3｜币种与金额单位（P0）

- 有可靠币种列且全表只有一个非空、可识别币种时，展示识别值并让用户确认；人民币/CNY/RMB 可显示“元”，其他币种保留明确币种标识。空币种或无法识别值不能被当作一种可信声明。
- 没有可靠币种列时，不默认“元”。用户可明确声明“人民币/元”、填写其他货币单位，或选择“单位待确认”。选择“单位待确认”可继续做数值汇总，但所有金额卡片、报告、图表和汇总表都须显式标注单位未确认；数字核对状态与单位确认状态分别展示。
- 一个文件含多种币种时继续阻断混算；v0.7 不做换汇。用户声明的单位及其来源（字段识别/人工声明/待确认）写入任务与依据文件，重开历史任务时保持原样。
- 金额单位不得只在报告正文中修正，网页事实卡、图表轴或图注、汇总表及模型可引用的事实卡要一致。

### F4｜跨周结论一致性（P0）

- B 口径下，凡系统判定订单跨自然周导致归属不明，环比、金额差额、渠道变化、贡献占比及模型总结中的跨周判断一律不可用；结果页和报告给出同一个原因。
- 若归属争议影响所选报告周自身金额，不得将该周金额标为“已核对的周金额”；要求修正数据或改走适用的全表汇总路径。不能仅隐藏环比却保留看似可信的周金额。
- 跨周结论的生成条件集中由同一份计算结果控制；网页、`report.md`、`data_summary.xlsx`、图表和 `analysis_basis.json` 不得互相矛盾。历史任务继续保留原结果，不在后台静默改写。

### F5｜全表汇总文案与口径（P1）

- 无可靠日期或用户明确选择不按周统计时，产物标题为“销售数据汇总”，事实卡使用“全表总销售额”等名称，并写明“统计范围：全表”。
- 模型提示、正常总结、模型失败后的确定性降级摘要、图表标题及不可用提示，都不得暗示本周、上周、环比或周趋势；不生成需要可靠周归属的图表。
- 汇总模式仍可展示全表可核对的总额、明细行数、订单量及适用的商品/渠道信息；未生成项目写清原因。

### F6｜结果页口径与限制摘要（P1）

- 在结果页事实卡之前显示：源文件名称、统计范围、销售额列、A/B 金额口径、货币单位及其确认状态、报告周与对比周（如适用）、数据质量限制和不可比较原因。
- 这份摘要从本次任务冻结的依据读取；刷新或从历史任务打开时仍显示当时的结论，不读取当前页面临时选择。
- 页面用普通业务语言解释限制，提供“返回重新检查并生成新任务”的入口；旧任务和产物不被覆盖。

## 5. 数据、隐私与接口约束

- 继续使用本地授权数据目录与独立成果目录；原始文件只读。同名上传不覆盖，成果覆盖需人工确认。
- 任务保存当前字段映射、文件指纹、A/B 口径、单位来源、周范围、人工完整性确认、计算与核对状态、不可用原因；重启后可恢复。依据文件不保存客户姓名、电话等原始个人信息。
- 接口成功与失败结构沿用现有约定；业务错误统一为 `{"error":{"code","message"}}`，不泄露堆栈或原始敏感单元格。异步任务失败时状态和可操作原因可从历史任务查到。
- 模型仍只接收脱敏、已确定可用的事实；不能通过模型推断币种、补足缺失对比周或替用户确定订单归属。模型失败继续降级并标注。

## 6. 验收场景

| 场景 | 通过条件 |
| --- | --- |
| 第 1、3 周有数据，第 2 周无记录 | 选第 3 周生成成功；第 3 周数字核对通过；第 2 周显示“无记录”；无环比、差额和变化事实，且不拿第 1 周替代。 |
| 对比周有记录且净金额为 0 | 任务成功；展示两周金额与差额，环比百分比不可用并说明分母为 0。 |
| 手动把销售额列换成含空值的另一列 | 质量计数和阻断立即对应新列；生成前被阻断；修正或换回有效列后可继续。 |
| 手动更换日期列 | 周列表、周覆盖与日期错误计数重算；旧报告周和完整性勾选清空。 |
| 无币种列 / 单一 USD / 多币种 | 无列时不自动写“元”；单一 USD 经确认后全产物用 USD；多币种不混算。 |
| B 口径订单跨周 | 若周金额归属不明，不出“已核对”周金额及任何跨周变化结论；页面和文件原因一致。 |
| 全表汇总且模型失败 | 标题、事实卡、降级摘要和图表说明均按全表口径，无本周、环比等周报措辞。 |
| 历史任务与重启 | 重开后能看到当时的字段、单位、周范围和限制；原表指纹不变，旧任务未被新任务覆盖。 |
| 桌面与 390px 移动宽度 | 口径摘要、错误与下载入口可读可操作，无页面级横向滚动。 |

## 7. 范围边界与版本闸门

v0.7 只修可信计算与结果解释，不加入本地口径预设、多文件/多工作表合并、自由问答、预测、自动归因、PPT、云同步、多人协作、定时发送或公网部署。本地口径预设待 v0.8 真实样表验证后再排期。月度成本上限沿用不超过 500 元；本版不创建收费云资源。

开发验收需覆盖上表场景的自动化和浏览器实测，核对报告、网页、图表、汇总表及依据文件一致性，并按项目规则提交证据包与阶段闸门是否表。真实 Ollama 和 5～10 份脱敏真实样表尚未验证前，须继续标“待验”，不能宣布产品质量验收或 1.0 就绪；v0.8 专门关闭这些待验项。
