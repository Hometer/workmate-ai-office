# PRD v0.4｜WorkMate 本地销售数据周报

> 日期：2026-09-28  
> 状态：M3 本地网页已可运行；真实模型与真实用户样表尚未验收。  
> 版本关系：继承 v0.3 已确认的目标用户、单机场景、交付物和隐私边界。本版确认订单量口径，并把代码复核发现的问题转为明确的产品要求与验收条件。v0.3 保留作历史版本。

## 0. 本版改了什么

| 项目 | v0.4 结论 |
| --- | --- |
| 订单量口径 | 有完整订单号时按订单号去重，另列明细行数；无完整订单号时不推断订单量 |
| 客单价 | 仅在订单量可确定且大于 0 时计算，总销售额 ÷ 去重订单量 |
| 无订单号的报告 | 显示数据行数；订单量和客单价显示“待确认”，不把行数冒充订单数 |
| 上传原始表 | 校验扩展名、实际可读取性和大小；同名文件不得直接覆盖 |
| 结果可用性 | 报告、三张图和汇总表都必须实际打开；图片占位符不算通过 |
| 任务失败与恢复 | 显示可读的失败原因，状态持久化；运行中重启后的处理仍需补齐 |

## 1. 产品定位与目标用户

WorkMate 是本地优先的销售数据周报助手。用户选一张销售表，输入一句任务指令，程序在本机读取、计算、画图，调用本地模型写总结，交付可查看、可下载的周报成品。数据默认不出本机。

首期用户为每周整理销售数据的运营、销售、个体店主和小团队负责人。首期为单机单用户产品，不要求登录；计划由 5 位种子用户分别在自己的电脑上试用。种子用户名单仍待确认。

首期只解决通用销售数据周报。PPT、跨会话记忆、第二业务场景、多用户协作、云端部署均不在本地 MVP 的交付范围。

## 2. 用户要完成的事

1. 在本地网页选择 `data/` 内的销售表，或上传一张 xlsx/csv。
2. 输入“做成销售周报”这类指令并提交。
3. 看见任务正在处理、已完成或失败；失败时知道原因。
4. 查看报告正文和三张图，下载汇总表。
5. 刷新页面后从历史任务找回已完成的结果。
6. 核对关键数字，决定是否采用成品。

交付物固定为 `report.md`、`charts/` 下的销售趋势图、Top5 商品图和渠道占比图，以及 `data_summary.xlsx`。原始表只读，所有成品写入独立成果目录。

## 3. 数据输入与指标口径

### 3.1 支持的数据

- 首期正式支持 xlsx/csv。文件必须位于授权数据目录，或通过网页上传到该目录。
- 上传时校验扩展名、文件大小和实际可读取性，拒绝伪装成表格的文件。
- 同名上传不得覆盖原始文件；用户改名后可以再传。
- 自动识别销售额、日期、商品、渠道、订单号等常见列名。销售额列是生成周报的必需列；缺失时明确报错。
- 文件中可能含客户姓名、电话等个人信息。日志不能记录完整表格内容、个人信息或完整任务指令。

### 3.2 订单量与明细行数

这两个数字同时保留，不能相加、取平均或互相冒充。

| 指标 | 计算方式 | 何时展示 |
| --- | --- | --- |
| 明细行数 | 实际读取到的数据行数，不含表头 | 每张有效表均展示 |
| 订单量 | 去掉订单号首尾空格后，统计不同订单号的数量 | 订单号列存在，且每条明细都有非空订单号时展示 |
| 客单价 | 总销售额 ÷ 订单量 | 订单量已确定且大于 0 时展示 |

订单号列不存在，或任意明细缺少订单号时，订单量和客单价显示“待确认”；报告和汇总表仍显示明细行数。此时不自动用行数代替订单量。

例如一张表有 4 条明细，订单号依次是 A001、A001、A002、A003，销售额合计 300 元。报告应写“4 条明细、3 笔订单、客单价 100 元”。如果没有订单号，应写“4 条明细、订单量待确认、客单价待确认”。

拿到第一张真实样表时，还要确认“销售额”是每行商品金额，还是在多行中重复填写的整单金额。若整单金额重复，直接逐行求和会高估总销售额；在确认字段含义前不能宣称数字已验收。

### 3.3 其他指标

| 指标 | 计算方式 | 缺失时 |
| --- | --- | --- |
| 总销售额 | 经有效性检查后汇总销售额列 | 缺销售额列则拒绝生成 |
| 环比增长率 | 最近一周与上一周销售额之差 ÷ 上一周销售额 | 日期不足或上周为 0 时显示“本表无此数据” |
| Top5 商品 | 按商品销售额降序，最多取 5 个 | 无商品列则不编造排名 |
| 渠道占比 | 各渠道销售额 ÷ 总销售额 | 无渠道列或总额为 0 时不编造比例 |

销售额列若存在无法解析的值，应明确报错并指出需要清理的列，不能悄悄把这些值当作 0。此项列入本版待修复清单。

## 4. 报告与网页要求

报告按“核心结论 → 关键数字 → Top5 商品 → 渠道表现”的顺序组织。关键数字至少列出总销售额、明细行数、订单量、客单价、环比增长率；不具备计算依据的指标明确标为“待确认”或“本表无此数据”。模型总结只能引用已经计算并核对的数字，不能自行补造订单、趋势或百分比。

网页应提供文件选择与上传、指令输入、任务状态、报告正文、三张图、汇总表下载和历史任务。成功状态必须以实际产物可读取为准。图表 `<img>` 加载失败时应显示明确失败提示，不能只显示破图占位。上传和任务失败都应给用户可理解的原因。

mock 模式只用于开发和演示，页面必须明确写明“总结未调用真实模型”。有模型服务时仍需完成真实输出、数字审核和人工样例评分，不能拿 mock 通过数替代。

## 5. 安全、状态与异常

- 只读取授权数据目录，只写入成果目录；原始文件永不改动。
- 覆盖已有成品须有明确二次确认，网页上传同名原始表直接拒绝。
- 任务状态、结果和错误原因落盘，服务重启后可查询已完成任务。
- 运行中的任务遇到程序异常时标记失败并显示通用错误，不向网页暴露堆栈。
- 服务在任务运行中退出后，不能让任务永久显示“进行中”；须恢复任务，或标记“已中断、可重新生成”。该能力目前待修复。
- 日志只记录任务 ID、状态、耗时和错误代码，不记录密钥、完整指令、完整表格或个人信息。
- 正式对外上线前再处理多用户登录与后端数据隔离；本地 MVP 不扩大为多人服务。

## 6. 验收条件

| 场景 | 通过条件 |
| --- | --- |
| 有重复订单号 | 同时显示去重订单量和明细行数；客单价以去重订单量为分母 |
| 没有或部分缺失订单号 | 明细行数可见；订单量和客单价为“待确认”，总结不写臆测数字 |
| 销售额字段异常 | 明确失败，不能静默忽略异常数值后交付 |
| 正常生成 | 报告、三张图、汇总表都实际打开；原始表哈希不变 |
| 上传异常 | 假 xlsx、超大文件、非法扩展名被拒绝；同名文件不覆盖 |
| 任务异常 | 页面显示失败原因；重启后状态可查询；运行中断不会永久转圈 |
| 隐私与模式 | 日志不含完整输入；mock 页面有明确提示；无密钥进入仓库或前端 |
| 真实模型 | 用 5～10 条真实样例检查数字、图表、总结可读性，并由产品经理评分 |

桌面和 390px 移动端都要检查。自动测试覆盖计算口径、缺失订单号、上传、文件下载、失败状态和目录边界；真实浏览器检查图片是否真正加载。正式验收必须使用真实模型和真实样表。

## 7. 2026-09-28 代码复核问题

| 发现 | 影响 | 当前状态 |
| --- | --- | --- |
| 图表文件链接返回 404，旧截图中的三张图是破图占位 | 用户拿不到完整成品 | 已修复并重拍桌面、移动端截图 |
| 上传只看文件名；伪造 xlsx 可上传，同名文件可覆盖 | 误导用户并可能损坏原始表 | 已修复，新增内容校验与同名拒绝 |
| 失败任务页面只显示空对象；意外异常可能一直“进行中” | 用户无法判断失败原因 | 已修复异常持久化与可读错误；进程退出时的任务恢复也已修复（启动时标记 INTERRUPTED） |
| 日志记录完整任务指令 | 指令可能含个人信息 | 已移除完整指令日志 |
| mock 总结没有在页面显式说明 | 演示结果可能被误认作真实模型输出 | 已增加演示模式提示；真实模型仍待验 |
| 数字核对调用与主计算相同的函数 | 能发现结果被篡改，难以发现公式自身写错 | 已修复：verify_metrics 独立重算，不调用主计算函数 |
| `.xls` 被列为允许格式，但未配置旧版 Excel 读取引擎 | 用户上传旧版文件可能失败 | 已修复：首期统一限定 xlsx/csv，移除 `.xls` |
| 销售额无法解析时可能被忽略 | 总额可能偏低而未报错 | 已修复：非空但无法解析的销售额显式报错 BAD_SALES_VALUE |
| 打开历史任务后文件下拉仍保留先前选择 | 用户可能误认结果对应的输入表 | 已修复：点历史任务同步文件下拉与指令框 |

已修复问题已有自动测试覆盖；此前的旧证据不能替代本轮复核结果。当前 mock 自动测试结果记在 `docs/项目状态.md` 和 `docs/evidence/阶段3-M3/`。
