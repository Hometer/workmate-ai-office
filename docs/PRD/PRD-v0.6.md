# PRD v0.6｜WorkMate 可信销售周报修复与真实验收

> 日期：2026-09-29  
> 状态：基于代码、65 项自动测试、隔离数据接口闭环和真实浏览器复核形成的待确认产品稿；本文件不代表功能已开发或验收。  
> 版本关系：继承 v0.5 的目标、A/B 金额口径、自然周、事实卡与本地隐私边界。v0.6 优先修复现有实现与 v0.5 验收要求之间的差距，之后再安排 v0.5 的 P1「本地口径预设」。

## 1. 产品目标与用户

WorkMate 面向每周要交销售周报的运营、销售、个体店主和小团队负责人。用户在自己的电脑上导入一张 xlsx/csv，确认字段、金额含义和报告周，得到可核对、可下载、可找回的销售周报。首期仍为单机单用户，默认使用本地模型，原始表只读，数据不主动发往云端。

**本版目标**：让「成功生成」同时意味着输入已通过全表检查、金额与时间口径得到确认、数字及结论有依据、结果在桌面和手机宽度都能查看。没有真实模型和真实销售样表前，只能称为开发验证通过，不能称为产品验收完成。

## 2. 当前实况与问题

### 2.1 已验证可用

- 现有项目的 65 项自动测试通过。隔离的 4 行示例表经检查、创建任务、生成报告、汇总表、依据文件和三张图，报告周总额 300、2 行、2 单、环比 100%；原表哈希未变，重新创建应用对象后任务仍可查询。
- 本地网页可按「选表 → 检查与口径 → 选周 → 结果」操作。桌面浏览器中报告与三张图可打开，mock 模式有明显提示。
- 现有代码提供 A/B 金额计算、自然周筛选、独立数字核对、任务持久化和统一业务错误结构。这些能力仍需通过下面的异常场景和真实数据验收。

### 2.2 本轮发现的缺口

| 编号 | 优先级 | 复核发现 | 用户影响 |
| --- | --- | --- | --- |
| G1 | P0 | 2 行中有 1 行空销售额时，`/api/v1/inspect` 返回 HTTP 500；检查结果中的空值无法安全序列化。 | 常见脏表卡在检查页，用户看不到可执行的修正提示。 |
| G2 | P0 | 表格没有可识别业务列时，检查接口的 `preview` 返回「客户姓名」等个人信息列原值。 | 本地页面和接口暴露了本不应展示的个人信息。 |
| G3 | P0 | 直接调用创建任务接口，不传金额口径及字段确认也会受理；后端默认 A。 | 可绕过界面确认，重复整单金额会被误加。 |
| G4 | P0 | 检查页有无效日期提醒，但选择报告周后按有效日期筛选；无效日期行可能被排除，依据文件的排除清单仍为空。空金额也未按 v0.5 要求阻断。 | 周报可能少算且不告知用户。 |
| G5 | P0 | 390px 浏览器实测页面横向滚动宽度达到 1045px；图表撑破结果区。 | 手机查看图表与下载入口困难。 |
| G6 | P0 | 网页没有历史任务入口；刷新后无法在页面找回任务，尽管后端保留了任务列表。 | 用户无法完成每周复用与复核。 |
| G7 | P0 | 周范围页未显示两周各自的有记录天数、有效行数、日期错误数与数据边界；切换报告周会重建复选框，但应用状态可能沿用旧周的「完整」确认。 | 用户无法判断完整性，也可能把旧确认用于新周。 |
| G8 | P0 | 后端可接受调用方传入任意对比周与完整性标记；计算前先过滤到报告周，跨周同订单的 B 口径归属冲突可能漏检。 | 环比和 B 口径的周金额可能被错误确认。 |
| G9 | P0 | 总结只做宽松文本与数字检查，未强制 200 字、事实卡引用或结构校验；对比周指标未独立核对，却可能出现「已核对」环比卡。 | 结论的可追溯性和「已核对」标识不可靠。 |
| G10 | P1 | 金额单位固定写「元」，缺少币种检查；报告、汇总表没有完整展示不可用原因和口径确认；README 仍把 v0.4 写作当前要求。 | 真实样表含币种或异常时容易误读，文档与产品不同步。 |

以上是本次已复现或由代码路径直接确认的缺口。性能、真实模型文风和不同来源销售表的兼容性尚未实测。

## 3. 用户主链路与交付物

1. **选表**：从授权数据目录选择，或上传不超过 20 MB 的 xlsx/csv；显示文件名、行数、日期跨度。上传不得覆盖同名原表。
2. **检查**：检查全表，建议销售额、日期、商品、渠道、订单号映射；用户可纠正。展示质量计数与阻断原因。默认不展示个人信息原值。
3. **确认口径**：用户明确选择 A「每行金额」或 B「整单金额重复」。没有选择不能提交任务；后端按同一规则验证。
4. **选周**：默认最近有记录的自然周，对比周固定为紧邻前一自然周；逐周展示覆盖情况，用户分别确认完整性。无可用日期时走「销售数据汇总」。
5. **生成和复核**：确定性计算与独立核对后，再生成总结与可用图表。结果先呈现关键事实，再呈现总结、图表、依据、下载和不可用原因。用户可在历史任务中找回当时的口径与结果。

每个成功任务保存 `report.md`、`data_summary.xlsx`、`analysis_basis.json` 和实际可计算的图表。缺少某张图时保存并展示原因；不要求所有数据表都产出三张图。重新确认口径后创建新任务，旧任务及其产物保持不变。

## 4. P0 功能与业务规则

### F1 全表检查与隐私

- `inspect` 对空金额、空日期、非法日期、空表、未知列名都返回稳定的 JSON 和业务提示，不返回 HTTP 500 或堆栈。JSON 中不得含 NaN、Infinity。
- 全表统计销售额和日期各自的有效、空、无法解析行数，订单号完整率及重复数；预览明确只含最多 5 行，统计口径明确为全表。
- 空金额或无法解析金额阻断金额计算，并给出行数与修正办法。任何排除须列出原因、行数、受影响指标；不能静默当作 0。
- 日期有空值或无法解析时，不直接生成看似完整的周报。用户可以修正源表，或明确选择「全表销售数据汇总」；汇总路径不出现本周、环比、趋势等措辞。日期错误不能在周筛选时无声消失。
- 预览采用允许列表，仅输出确认参与计算且不属于疑似个人信息的列。即使字段识别失败也返回空预览或安全提示；接口错误、日志、模型输入都不包含原始行值、客户姓名、电话、邮箱或地址。

### F2 字段与金额口径确认

- 销售额列必选且必须属于当前文件；字段重名或多个候选时要求人工确认。所有映射在后端校验，不能只依赖前端按钮状态。
- `amount_mode` 只能是 A 或 B，且是用户本次明确选择的值；缺失、非法值、未完成检查确认时拒绝创建成功任务。CLI 也应明确传入口径或提示选择，不能默认为 A 后宣称口径已确认。
- A 汇总每行金额。B 要求每行完整订单号；同订单多行金额必须一致，每订单只记一次。订单跨日期、跨自然周或跨渠道且无法统一归属时，相应周金额、趋势或渠道指标不得出具「已核对」结论。
- 订单量仅在统计范围内每行都有完整订单号时按去重订单号计算；明细行数单独展示。客单价仅在订单量确定且大于 0 时计算。B 模式下多商品整单金额不分摊给商品 Top5。
- 负数按原值纳入，但标注负数行数；多币种数据不得混算，若没有可靠币种字段或单一币种声明，报告单位不得无条件写「元」。

### F3 报告周与环比

- 自然周按用户本机时区的周一 00:00 至下周一 00:00。报告与依据文件记录周一、周日及时区；对比周只能是报告周前一自然周，由后端推导并验证。
- 周选择页展示两周有效记录数、有记录天数、日期空/错误行数和与源文件日期范围的关系。用户切换报告周后，清空两周完整性确认。
- 只有两周金额可计算、日期可归属、口径一致且分别确认完整，才出环比。对比周为 0 时只列金额与差额。每种不能比较的情况显示具体原因。
- 后端不能只信任调用方的 `complete` 布尔值。至少校验选周合法、前后周相邻、无未处理日期错误、B 口径跨周订单归属明确；人工确认记录在任务里。

### F4 事实卡、模型总结与产物一致性

- 事实卡记录值、单位、源列、计算式、统计范围、排除数和核对状态。「已核对」仅用于确实经过独立校验的指标；环比还要校验对比周金额。
- 模型只接收脱敏后的事实卡，生成不超过 200 字的中文总结。每条含数字的结论标注对应卡片编号；不臆测原因、利润、退款或运营动作效果。输出经结构与引用校验，不合格时有限重试并降级为明确标注的确定性摘要。
- `report.md`、网页事实卡、图表、汇总表和 `analysis_basis.json` 使用同一冻结计算结果。依据文件记录字段映射、A/B 选择、周范围、完整性确认、排除数、公式版本、双周核对结果和源文件指纹，不存原始个人信息。
- 任务成功以所有声明交付的文件可读取为准；模型降级、不可用图表、缺失字段和无法比较的原因在结果页与下载文件中可见。

### F5 页面可用性与恢复

- 桌面和 390px 移动宽度均无页面级横向滚动；图表在结果容器内按宽度缩放。关键操作支持键盘，错误不只靠颜色表达。
- 网页提供历史任务列表，可打开已完成及失败任务；刷新后可从任务 ID 找回运行状态或结果。服务中断后的任务显示「已中断，可重新生成」，不永久转圈。
- 防止重复提交创建多个任务；文件或周选择变化时，旧映射、金额口径和完整性确认不得错误沿用。失败时保留用户已填的可用信息，给出可操作提示。

## 5. P1 与范围边界

P0 真实验收后再做「本地口径预设」：按列结构指纹带出字段映射和 A/B 选择，用户每次确认；不复用上周的日期与完整性确认，可删除预设，不保存原始行值。

本版不做 PPT、多文件或多工作表合并、自由问答、自动归因和预测、云同步、定时发送、多人协作与公网部署。若未来开放公网访问，必须先加入登录与后端数据隔离，并单独完成上线验收。

## 6. 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 空金额与坏日期 | 检查接口均为可读 JSON；空金额阻断；坏日期要求修正或明确切全表汇总，不可静默过滤。 |
| 隐私预览 | 仅有「客户姓名、备注」的表可检查且不返回姓名原值；日志、模型输入与错误响应也不含原始个人信息。 |
| 绕过页面提交 | 不传金额口径、传 C、传不存在的销售额列、传不相邻的对比周均被后端拒绝，不创建成功任务。 |
| 重复整单金额 | A 模式下 100+100+50=250；B 模式下两笔订单总额 150、客单价 75。B 的金额冲突、缺号、跨周归属冲突有准确阻断或不可用原因。 |
| 周比较 | 第 1 与第 3 周有数据而第 2 周为空，选第 3 周不能拿第 1 周做环比；切换周后重新确认完整性；对比周为 0 不输出百分比。 |
| 证据一致 | 报告、网页、图表、汇总表与依据文件的统计范围和数值一致；故意篡改任一周校验值时任务失败。旧任务仍可打开旧口径。 |
| 结果页面 | 390px 无页面级横向滚动，三张实际生成的图能加载；刷新后通过历史任务找回报告、下载及失败原因。 |
| 真实模型与样表 | 本地 Ollama 真实生成至少一份；再用 5～10 份经授权且脱敏的真实销售表，由产品经理核对数字、图、总结并打分，关闭 D2/D3。无模型或样表时标「待验」。 |

## 7. 非功能与交付闸门

- 本地数据目录白名单、20 MB 上传限制、格式与真实类型校验、同名原表不覆盖、成果目录白名单与显式覆盖确认继续生效。密钥不进仓库、前端、日志和证据图。
- 错误统一为 `{"error":{"code","message"}}`，不返回堆栈或原始敏感单元格；任务状态、人工确认、结果和错误在服务重启后可查。
- 自动测试、真实浏览器桌面/移动检查、真实模型冒烟、真实样表评分、README 更新和证据包逐项记录。任何未通过项保留「否/待验」，不宣布 v0.6 或阶段 3 完成。
- 当前成本上限沿用每月 500 元；本版不创建收费云资源。

## 8. 待产品经理确认的业务事项

已定决策继续有效，不重复追问。首次取得真实样表时确认销售额字段是否含税、退款、整单重复金额或币种；首次真实模型冒烟时对 5～10 份结果打分，确定可读性和瑕疵容忍度。正式试用前确认种子用户与企业认证情况。以上事项当前均不阻止编写修复方案，但会影响真实产品验收。
