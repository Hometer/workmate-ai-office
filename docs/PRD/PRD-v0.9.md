# PRD v0.9 WorkMate 办公体验与周报交付

> 日期：2026-10-02  
> 状态：2026-10-02 先交文稿和代表设计；产品经理暂停后明确要求继续，已沿用代表方向交付 A 代码及本机工程证据。真实模型、下载及重启通过，Safari/原生缩放/实机和最终视觉满意度待验，尚未宣布 A 全部验收完成。B/C/D 按闸门后续推进，新增使用效果目标仍待试用评审。  
> 开发基线：`67b6c85`，M3.8 工作台重设计及 v0.8 A 验收归档。  
> 版本关系：继承 [PRD v0.8](PRD-v0.8.md) 的可信计算、本地隐私与人工确认规则。建议将尚未开发的 v0.8 B 纳入本版复用与交付阶段，并保留原定的 5 名种子用户连续试用；不另设一套重复排期。

本版围绕每周制作销售报告，统一网页与图表的视觉样式，减少重复配置，并让报告能够继续编辑、回查和交付。用户应能顺利完成第一次报告，也能快速制作下一周报告。是否达到产品经理期望的成熟办公产品水平，以代表页面评审和实际使用结果判断。

## 1 目标用户与当前基线

### 1.1 目标用户与核心任务

目标用户继续为每周提交销售周报的运营、销售、个体店主和小团队负责人。核心任务保持为：导入一张销售表，确认计算含义和范围，得到数字可核对、能够直接用于汇报的报告。优先观察使用固定格式表格的重复周报场景。

主要使用终端为桌面浏览器，兼顾移动宽度的阅读与基本操作。单机单用户、原表只读、本地模型先行、数据默认不出本机的约定保持有效。

### 1.2 已有能力与验证边界

目前已有工作台、数据文件、历史成果和环境自检四个入口；支持上传、数据检查、字段映射、两种金额口径、单位确认、周范围、真实本地模型摘要、报告四页签、下载和历史恢复。后端检查响应已有脱敏预览，网页尚未呈现该预览。历史已有文件名搜索和状态筛选。

基线工程记录为 Python 172/172、Node 15/15，Lint、三个核心模块 strict checkJs、静态构建通过；已用授权合成表和真实本地 Qwen 完成网页生成、下载及实际重启验证。这些结果属于基线，不作为 v0.9 新功能的验证结果。企业真实表适用性、种子用户试用和手机实机体验仍待验证；M3.8 的视觉满意度尚未由产品经理确认。

## 2 输入 过程 产物与留存

| 项目 | 本版要求 |
| --- | --- |
| 数据输入 | 单张 xlsx/csv，继续执行 20 MB 限制、真实类型校验与安全文件名规则；同名原表不覆盖 |
| 制作配置 | 字段映射、金额口径、单位及来源、按周或全表模式；按周时选择周次并确认本次覆盖 |
| 预览 | 默认最多 5 行，只展示允许的业务列；疑似个人信息不显示原值，不能回退展示全表 |
| 口径预设 | 命名、字段映射、金额口径、人工声明单位和统计模式；不保存原始单元格、旧周次或旧完整性勾选 |
| 制作草稿 | 当前文件引用、步骤、配置与保存时间；与运行任务分开，不以草稿冒充已完成检查 |
| 报告修订 | 标题、用户备注、表达版式、引用关联、来源任务及修订记录；系统计算事实保持只读 |
| 既有成果 | 网页、`report.md`、适用图表、`data_summary.xlsx`、`analysis_basis.json`，继续可用 |
| 新增成果 | 可复制周报、PDF、Word；各自绑定明确的原版或已保存修订版 |
| 本地留存 | 草稿、预设、任务元数据、置顶与修订版本持久化；历史依据与原始成果保留 |

人工编辑内容可能含业务机密，继续只保存在本地成果范围，不进入日志、URL、模型输入或公共证据。预览不是全表质量检查结果，页面必须区分“预览 5 行”与“全表已检查”。

## 3 用户主链路

### 3.1 第一次制作

1. 打开工作台，看到清楚的制作入口、支持格式与本地处理说明；可使用明确标为样例的合成文件了解流程。
2. 上传或选择一张表，检查后看到安全预览、字段匹配和全表质量摘要。
3. 根据业务例子确认金额是商品行金额还是重复整单金额，确认单位，选择按周或全表模式。
4. 按周时选择有记录的报告周，确认本次覆盖情况；对比不可用时仍按既有规则交付适用结果和限制。
5. 提交后看到真实任务步骤；离开、刷新或连接中断后通过原任务恢复，不重复生成。
6. 报告先展示范围、必要限制、核心数字与结论；点击引用核对事实。需要时补充备注并保存修订版。
7. 复制或导出当前保存版本，检查交付预览；可主动保存已确认口径为下次使用的预设。

### 3.2 下一周重复制作

1. 从工作台或上次成果进入“沿用设置制作新报告”，选择本次数据文件。
2. 系统应用预设或历史配置副本，重新检查当前数据，展示已匹配项和冲突项。
3. 用户确认本次金额与单位，选择本次周次，重新确认覆盖；预设不携带上次的完整性授权。
4. 生成新任务，旧报告与旧确认记录不被改写。

### 3.3 修改与继续工作

报告修改在当前成果页进行。桌面可展开编辑面板与预览并排；移动宽度切换编辑和预览，主要操作可触达。保存修订后，复制和导出明确对应同一版本。若要改变销售金额、字段或范围，返回数据流程重新检查并生成新任务。

未提交配置恢复为制作草稿；已受理任务恢复为后端真实状态。源文件变化、确认过期或对应文件缺失时，保留可用输入并明确要求重新检查。

## 4 功能需求与通过条件

### V9-01 工作台首页

- 保留新建、上传、已有文件、最近任务和自检能力。首次使用呈现短引导与明确样例入口，不把样例数字混入用户成果。
- 有历史数据时压缩介绍与排版示意，首屏优先呈现继续草稿、最近成果和制作新周报入口。建议桌面 1280×800 时无需滚动即可看到至少一条最近工作。
- 正在运行、制作草稿、成功成果和失败任务分别表达。草稿尚未加载时不能显示“没有草稿”。

**通过条件：**空工作区与已有任务两种状态均可独立开始；最近工作能打开对应对象，无假入口、样例冒充或任务状态混淆。

### V9-02 图表与界面统一

- 日趋势、商品排名、渠道占比沿用实际计算数据。统一字体、字号层级、品牌配色、轴、网格线和图注，不改变数值与图表适用条件。
- 下载图保留统计范围、金额单位及重要限制；中文和长标签可读。负数、退款、零额和占比不能通过截断坐标或装饰处理产生误导。
- 预览支持放大与下载，保持加载、失败和重试状态。首轮可继续采用静态图，不为视觉统一强制引入交互图表库。

**通过条件：**网页与图片采用同一套规范；元、USD、单位待确认、按周与全表等适用场景下，图表数值、范围及限制与事实一致。

### V9-03 报告信息层级

- 报告名称包含可读业务名称与周期；全表模式使用“销售数据汇总”，不暗示本周或环比。
- 顶部保留范围、金额单位、总结身份和影响判断的重要限制。正文先给关键结论与数字；字段、公式和详细核对说明放入可展开口径摘要或依据区。
- 保留四页签与旧任务 URL 恢复。长正文、图表和依据页提供清楚的返回与交付操作，不让顶部操作占据移动端大量阅读空间。

**通过条件：**代表报告首屏能识别范围、状态、核心数字和结论；单位待确认、对比不可用及降级摘要的关键提示不会被折叠隐藏。

### V9-04 文字与阅读层级

- 默认正文建议 14—16px，报告正文建议 16px；辅助文字建议至少 12px，业务决策信息不用过小字号。具体数值通过代表页评审冻结。
- 深灰正文、清晰辅助文字、统一标题与行高。减少用浅紫文字承载长说明，金额和单位易于区分，数字显示精度沿用既有约定。
- 中文使用本机系统字体；图表和导出采用合法、支持中文的本地字体方案，不请求外部字体服务。

**通过条件：**桌面与移动宽度下关键文字可读，长文件名、长单位与大金额不遮挡；缩放至 200% 后核心操作仍可完成。

### V9-05 组件与状态规范

- 以克制、清晰、以成果为中心的办公工作台为统一方向，保留低饱和紫色主操作，使用中性色建立页面层级。
- 按 4/8px 节奏统一间距，明确卡片、按钮、输入、标签、菜单、对话框和提示的尺寸、圆角、阴影；覆盖悬停、焦点、禁用、提交、失败和成功。
- 沿用同一套图标；状态有文字或图形，不能只靠颜色。重要禁用操作说明原因，错误靠近相关字段。
- 显示后端真实步骤与恢复入口，不展示未经测量的剩余时间或伪造进度百分比；局部产物失败与整个任务失败分别说明。

**通过条件：**首页、确认页、报告页、历史页与异常页使用统一组件状态；键盘可完成主链路，弹窗关闭后焦点返回，减少动态效果偏好有效。

### V9-06 周报预设与明确统计模式

- 承接 v0.8 F6。用户主动保存、命名和应用预设；也可从历史成果复制配置制作新报告。
- 应用配置后重新检查本次文件。缺列、字段歧义、币种变化、多币种或订单号不足明确提示，不能静默修改口径或直接放行。
- 人工声明单位可作为待确认配置带入；字段识别币种必须从本次数据重新识别。无可靠单位仍标待确认，不默认元。
- 明确提供按周与全表模式。有日期字段也可以选全表；不要求用户清空正确的日期映射来改变模式。
- 保存与覆盖预设有清楚结果；覆盖同名预设须确认，历史任务不随预设更新而改变。

**通过条件：**下一周可复用配置并生成新任务；旧周次与完整性勾选不继承，冲突必须解决或重新确认，实际重启后预设仍可读取。

### V9-07 安全预览与业务口径说明

- 优先展示既有检查接口提供的最多 5 行安全预览，并在字段选择旁给出允许展示的示例值；全表质量统计继续单独呈现。
- 默认不显示客户姓名、电话等疑似个人信息原值；订单号示例只给掩码或结构说明。字段映射失败时不回退全列展示，预览不进入模型或日志。
- 金额口径使用“每行是商品金额，相加统计”和“整单金额在多行重复，按订单去重”。说明例子明确标为教学示例：同一订单两行各 100，前者合计 200，后者合计 100。
- 修改字段后预览、质量统计、阻断和周信息均按新映射重检；检查失败保留选择，并明确告诉用户如何恢复。

**通过条件：**用户能根据样例判断金额含义；隐私原值不泄露，预览更新与当前映射一致，继续操作不能绕过后端确认校验。

### V9-08 报告编辑与版本保留

- 首轮编辑范围限定为业务标题、人工备注、章节表达与预设摘要版式。销售事实、单位、范围、公式和必要限制保持只读；不做完整 Word 编辑器。
- 提供完整周报与简短汇报版。简短版从同一份可用事实中选取和排版，沿用模型只选择事实、确定性渲染的约束，不开放无约束 AI 改写。
- 用户备注明确标“人工补充”，不自动标为数字核对或 AI 事实验证通过。新增或改变统计指标须返回数据检查；用户备注不自动发给模型，也不让模型自行增加原因、预测或建议。
- 编辑草稿与已保存版本区分；保存后追加修订版本，显示来源任务和时间，允许查看原版与恢复为新修订，原始报告和事实不覆盖。
- 导出前检查当前保存版本。未保存变更提示先保存或明确使用上次保存版本；保存失败时保留输入。并发修改冲突提示重新读取，不静默覆盖。

**通过条件：**改标题、补备注、切简短版、保存、刷新、重启及恢复原版均可验证；系统事实不被修改，原版与修订版对应关系清楚，模型生成内容继续满足 D2/D3。

### V9-09 可点击的事实引用

- 网页将内部引用转为可理解的“查看依据”或引用编号，绑定本次任务中的实际事实标识。点击打开对应事实，显示值、单位、范围、来源列、公式及核对状态。
- 原版、简短版和修订版的系统结论继续携带引用。复制文本提供可读引用说明，PDF/Word 提供对应依据摘要，脱离网页仍可理解。
- 旧任务缺少事实关联、事实不可用或依据加载失败时明确提示；不构造不存在的证据，也不把错误引用自动判为通过。
- 本版回查到已有事实卡与计算依据。原表具体行定位列为后续候选，不把当前聚合依据描述为行级溯源。

**通过条件：**从销售额、订单量或适用比较结论能找到准确依据；相同数值的不同指标不串联，缺失依据与加载失败有正确提示。

### V9-10 复制与办公格式导出

- 承接 v0.8 F7，提供复制周报；富文本复制用于常见编辑器，并始终提供普通文本版本。权限受限或浏览器不支持时提供可选择的文本，不显示虚假成功。
- 新增 PDF 与 Word（`.docx`），先完成复制/PDF 闭环，再补 Word。复制、网页与两种文件均绑定明确的已保存报告版本。
- 包含标题、范围、单位、关键数字、适用图表、结论、可读依据及必要限制；降级、单位待确认和人工备注标识随交付保留。
- 导出完全在本地完成。中文不缺字，表格与图表不裁切，分页合理；Word 使用可编辑的正文与表格，图表可以为图片。
- 导出过程显示状态并防重复；失败不影响原报告，支持重试，不提供损坏文件或空文件作为成功结果。服务重启后已成功导出的文件仍可下载。
- 原 Markdown、汇总表、图表和依据下载继续保留。复制和下载由用户主动触发，不向群聊、邮箱、云盘自动发送。

**通过条件：**元、USD、单位待确认、全表、比较不可用与降级等适用样例的复制/PDF/Word 逐项核对通过；两种文件实际打开，数值与引用一致，长内容与中文版式可读。

### V9-11 历史成果管理

- 默认业务名称包含报告周期或全表范围；原始文件名作为来源信息单独显示，生成时间和状态保留。无周期的旧任务不猜测日期。
- 支持业务名称重命名、置顶、按周期筛选，以及文件名/业务名称搜索；保留已有状态筛选。列表展示原版或最新修订身份，区分同一文件的不同报告。
- 详情关联源文件、冻结配置、原始任务和修订记录，并提供沿用设置制作新报告；源表已变或不可用时明确提示，不用新文件解释旧结果。
- 重命名只改业务展示名称，不修改原表、旧文件路径和既有任务 URL。置顶与名称持久化，保存失败时界面恢复真实状态。

**通过条件：**同一表生成不同周期报告后可辨认和查找；重命名、置顶及重启不影响旧 URL、原始成果或下载。

### V9-12 制作草稿与可靠恢复

- 首轮提供一个当前制作草稿，自动保存最少必要配置并显示保存状态；开始新报告前，已有未完成草稿须明确保留或放弃，不能静默丢失。
- 草稿不存单元格原文、预览或凭据；恢复后重新检查源文件与当前映射。人工完整性授权不能仅凭浏览器勾选恢复，只有后端确认凭据有效且与数据版本一致时才可继续，否则重新确认。
- 草稿保存中、已保存、失败、待重新检查均有区分；网络失败保留输入并可重试。自动保存与恢复不创建生成任务、不触发模型。
- 提交获得任务 ID 后，草稿关联对应任务，首页不同时展示为两个正在生成的对象。提交结果未知时先查询原任务，不因恢复草稿自动重提。

**通过条件：**配置后刷新、关闭重开、导航返回及实际服务重启均能继续；修改或删除源文件后要求重检，重复提交与超时恢复不造成重复任务。

## 5 视觉方向与质量标准

### 5.1 代表页面先行

开发前先交付首页、字段确认页和报告页三张代表设计，采用同一套字号、颜色、密度与组件。至少同时展示桌面和 390px 排布，并包含一份单位待确认或降级报告，避免只评审正常空页面。

产品经理查看颜色、层级、阅读密度、按钮和图表后确认方向，再扩展全站。无需重复决定已有目标用户、口径和隐私规则。不能由执行者自行记录“大厂视觉水平已认可”。

### 5.2 延续已确认的数字质量

沿用 D2/D3：数字、范围、单位、隐私、原表只读、成果可打开与恢复等硬性要求全部通过；样例结论正确、引用准确、回查方便、表达适合交付四维每项至少 2 分，无不能接受项。任何错误不能被平均分抵消。

本版 UI 和导出须增强引用的可读性；已有内部标记在基线验收可接受，不意味着新交付格式可以省略依据。新模型调用或摘要版式仍按原标准验证，不用已通过的旧样例结果冒充新功能验收。

### 5.3 建议的使用效果目标

以下为本稿提出的试用目标，待范围评审确认；没有现成数据，不写为已达到。

| 观察项 | 建议目标与测量方式 |
| --- | --- |
| 首次独立制作 | 5 名试用者中至少 4 名，在本地服务就绪且已有可用样表的条件下，独立完成首次配置与提交；配置时间不超过 5 分钟 |
| 重复制作 | 每人进行第二次同格式表制作；至少 4 名独立完成配置与提交，时间不超过 2 分钟；仍须当前数据检查及人工确认 |
| 找到结论与依据 | 5 人中至少 4 人，在 30 秒内找到报告范围与主要结论，并在 30 秒内定位一条指定结论的依据 |
| 交付便利性 | 两轮共 10 次任务中至少 8 次，用户仅需不超过 2 分钟的文字或标题调整即可交付；任何数字或范围错误均判该次失败 |
| 视觉与阅读 | 产品经理确认三张代表页，并在全站评审时逐项检查字体、图表、层级和组件一致性，记录具体未通过项 |

时间从相关页面就绪开始计算，排除找文件、安装、模型运行和导出生成等待；等待时间另外实测记录，不能靠排除等待宣称端到端耗时达标。小样本只用于判断本轮产品体验，不推导全部用户的成功率。

## 7 模型 成本 数据与非功能要求

### 7.1 模型与成本

继续采用本地 Ollama + Qwen；月度预算不超过 500 元，不创建付费云资源。基线模型仅为已验证配置，后续各阶段记录实际型号、量化版本、耗时、首轮通过、重试和降级，不承诺未测性能。

模型仍只接收脱敏、可用且已核对的事实，输出必须结构与事实校验，具备超时、失败和有限重试。编辑、预设、草稿、复制和导出不需要自动调用模型；所有生成的业务文字不得增加无依据的数字、归因或预测。模型不可用时保留现有确定性降级及清楚身份，不静默切 mock 或云端。

导出与编辑依赖在阶段适配时评估，必须可本地运行；不因新增字体或包而自动下载运行时远程资源、改变数据格式或安装付费服务。

### 7.2 数据与兼容

- 原表、历史任务、既有测试和成果全部保留。新增元数据与修订兼容旧记录，缺失字段使用诚实兜底，不批量重写旧报告。
- 数据版本、人工确认、任务、草稿、预设、修订和导出状态均本地持久化。实际服务重启后验证恢复；内存状态或浏览器存储不能替代后端确认。
- 新导出写入独立成果白名单，避免覆盖原始产物；同名业务标题不直接作为文件路径。更新预设、修订和历史展示名称均不得改变历史计算依据。
- 敏感原文与个人信息不进入模型、日志、URL、Git 或公共证据；新预览与导出继续检查安全内容和文件名。
- 实施前在阶段文档明确新增接口的请求、响应、错误、超时、幂等性和兼容性。统一返回 `{"error":{"code","message"}}`，不暴露堆栈。

### 7.3 可用性与工程质量

继续使用现有 FastAPI 与静态前端架构，不为视觉要求强制技术替换。新增核心业务模块严格类型检查，DOM 编排沿用已有适配与真实浏览器验证，不宣称全量 TypeScript 覆盖。

至少检查 390/768/1280/1440px。窄屏表格受控滚动或重排，图表可放大，触控主操作至少 44px；键盘可完成核心流程。目标桌面浏览器包括实际验证的 Chromium 和 macOS Safari；未经实测的浏览器/设备列为待验。

正常核心页面无持续脚本错误、资源失败或重复请求。列表规模、编辑器和导出性能先测量；新能力按需加载，不引入与当前任务无关的重型库。普通交互和保存提供及时反馈；生成与导出耗时按样表行数、设备和环境记录。

工程阶段可沿用已授权合成样表测试，明确输入身份；D 使用经授权真实业务表及独立人工答案。没有真实试用者或业务表时，D 保留待验，不把代验视为连续试用完成。手机实机与可达条件单独记录，桌面验收不冒充手机实机通过。
