# 阶段 2 第 1 子阶段技术开发文档｜M1 骨架

> 配套文档：PRD v0.3、《AI Agent 产品 Vibe Coding 通用技术栈手册》V2.1、《技术适配声明》。
> 本文档只覆盖 M1 骨架。AI 开发时不得提前实现 M2/M3/二期能力。

## 一、阶段目标

- **交付范围（对齐 PRD §8.2 M1）**：单进程跑通"一句话 + xlsx/csv → 销售周报成品"的端到端链路，CLI 交付。
- **阶段产物**：一个可本地运行的 CLI 程序，给定授权目录内的销售表，产出成品文件夹（`report.md` + `charts/`（3 张图）+ `data_summary.xlsx`），并返回"成果清单 + 改动说明"。
- **验收标准（对齐 PRD §3.3，M1 子集）**：
  1. 指标数字与原始数据核对一致（M1 靠 mock 测试 + 人工抽查保证；自动 `verify_metrics` 在 M2 补）。
  2. 图表能正常打开、表达正确。
  3. 总结不编造数据、有结论、可读。
  4. 成品落盘成功，原始文件未被改动（M1 强制红线）。
- **明确不做**（防范围蔓延）：
  - `verify_metrics` 自动数字核对 → M2
  - `safety_check` 内容审核 → M2
  - 权限目录白名单、覆盖已有文件二次确认的完整硬化 → M2（但"原始文件只读、成品写独立目录"这条红线 M1 就强制）
  - 日志系统 → M2
  - 本地网页 UI → M3；PPT 输出 → 二期
  - 模型驱动的自由任务规划（M1 用固定标准周报管线，模型只负责"写总结"）
- **本阶段打通的主链路片段**：
  `一句话 + 文件 → search_files 定位 → read_file 读表结构 → compute_metrics 算指标 → plot_chart 画图 → 模型写总结 → write_file 落盘 → 返回成果清单`

## 二、技术适配摘要

- 引用《技术适配声明》结论：后端先行（路径 A），本地优先，数据不出本机。
- 本阶段采用：Python 3.12 + `.venv`、Pydantic、pytest、Git、Ollama 本地模型（qwen 系）+ mock 兜底。
- 本阶段启用按需模块：pandas + openpyxl（读表/算指标）、matplotlib（画图）、带 schema 版本的文件持久化（JSONL 轨迹 + JSON 任务状态）。
- 本阶段偏离/暂缓：
  - **FastAPI 本阶段不引入**（对技术适配声明的细化）：M1 是 CLI，没有 HTTP 消费方，工具做成可独立调用、可测试的 Python 函数即可；M3 做本地网页 UI 时再挂 FastAPI，工具函数保持可复用。
  - 数据库、SSE、RAG、docx、PDF 均不引入（同技术适配声明）。
- 开发路径：后端先行。

## 三、技术栈与模型

| 组件 | 用途 | 本阶段是否引入 |
| --- | --- | --- |
| Python 3.12.x + `.venv` | 运行环境 | ✅ |
| pandas + openpyxl | 读 xlsx/csv、本地算指标、导出汇总表 | ✅ |
| matplotlib | 画趋势图/Top5/饼图 | ✅ |
| Pydantic | 结构与错误校验 | ✅ |
| pytest | mock 自动化测试 | ✅ |
| Ollama（HTTP API）+ qwen 系 | 本地模型：写总结（M1 唯一用模型的环节） | ✅（未装时用 mock 兜底） |

**模型选型**：Ollama 本地 `qwen2.5:7b`（写总结，够用且免费、不出本机）。通过 `.env` 的 `WORKMATE_OLLAMA_MODEL` 可改。无 Ollama 时自动降级 `mock` 提供商（返回确定性总结，明确标注为 mock）。

## 四、环境与配置

- 配置项（不含秘密）见 `.env.example`：

```
WORKMATE_DATA_DIR=./data          # 授权数据目录（放 xlsx/csv）
WORKMATE_OUTPUT_DIR=./outputs     # 成品目录
WORKMATE_MODEL_PROVIDER=ollama    # ollama | mock
WORKMATE_OLLAMA_HOST=http://localhost:11434
WORKMATE_OLLAMA_MODEL=qwen2.5:7b
```

- 需要用户提供什么：**无 API Key**（本地模型免费）。唯一前置是装 Ollama 并拉取模型，验收前完成即可，M1 开发期用 mock。
- 启动方式：`python -m workmate run --file data/你的表.xlsx --instruction "做成销售周报"`（详见 README）。
- 外部依赖服务：Ollama（仅真实冒烟需要）；无端口占用需求（CLI 单进程）。

## 六、数据、资产与状态

- **持久化方式**：单机单用户、资产以文件为主、只有简单索引 → 用带 schema 版本的结构化文件，不引入数据库。
- **结构化文件**：
  - `outputs/.workmate/tasks.json`：任务状态（字段：task_id、status[created/running/done/failed]、instruction、input_file、created_at、updated_at、steps[]、schema_version）。schema_version=1。
  - `outputs/.workmate/trace.jsonl`：轨迹（每行一条：ts、task_id、step、event、payload 摘要；**不含个人信息、不含整表数据**）。
- **资产**：成品 `report.md`、`charts/*.png`、`data_summary.xlsx` 落 `outputs/<task_id>/`；原始数据文件只读、永不改动。
- **状态机**：任务 `created → running → done | failed`；步骤级记录在 `steps[]`。**恢复方式**：进程重启后读 `tasks.json`，`running` 且中断的任务可按已完成步骤续跑（M1 提供"重新执行"与"续跑"两个入口）。

## 七、工具设计（M1 五工具 + 模型层）

统一错误结构：`{"error": {"code": "...", "message": "..."}}`，不泄露堆栈。

| 工具 | 输入 | 输出 | 副作用 | 权限（M1 已强制部分） |
| --- | --- | --- | --- | --- |
| `search_files` | 关键词/目录 | 匹配文件清单 | 无 | 只搜 `WORKMATE_DATA_DIR` |
| `read_file` | 文件路径 | 表结构（列名/类型）+ 数据摘要（行数、抽样统计），不整表返回 | 无 | 只读；仅 xlsx/csv，≤20MB |
| `compute_metrics` | 指标名 + DataFrame | `{name, value, 依据}` | 无 | 本地确定性代码 |
| `plot_chart` | DataFrame + 图类型 + 输出路径 | 图片路径 | 写图 | 写 `outputs/<task_id>/charts/` |
| `write_file` | 路径 + 内容 | 写入确认 | 写文件 | **只写 `WORKMATE_OUTPUT_DIR`；拒绝覆盖原始数据文件** |
| 模型层 `complete` | system + user | 总结文本 | 无 | 本地 Ollama / mock |

**列名识别（read_file 之后的关键步骤）**：真实表列名五花八门。M1 内置常见别名映射（销售额≈sales/amount/金额/成交额；日期≈date/时间/日期；商品≈product/商品/产品/sku；渠道≈channel/渠道/来源；订单≈order_id/订单号/流水号）。识别不唯一或识别失败时，**返回"需人工确认列含义"的提示**（对齐 PRD §7.6），不瞎猜。

## 八、Prompt 设计

M1 只用一份 Prompt：**周报总结生成器**。

- 角色：WorkMate 数据周报助手。
- 输入变量：`{metrics}`（已算好的指标数字，来自 compute_metrics）、`{top5}`、`{channel_share}`。
- 输出格式：纯文本，`report.md` 正文，结构固定（PRD §3.6）：本周核心结论（一句话）→ 关键数字（总销售额、环比、客单价）→ Top5 表现 → 渠道表现 → 一条建议/风险提示；约 200 字，先结论后数据。
- 约束（写进 Prompt）：
  1. 只用给定数字，**绝不编造**；表里没有的指标写"本表无此数据"。
  2. 短、有结论，不要空话套话。
  3. 数字保留原样，不四舍五入到失真。
- 模型输出与结构化存储关系：模型只产出 `report.md` 正文文本；指标数字由 `compute_metrics` 结构化结果负责写入，模型无权改动数字。总结文本在写盘前做基础校验（非空、≤500 字），超出或为空则回退模板。

## 九、验收界面或纵向切片

本阶段**不需要最小界面**。产出是 md + 图表 + xlsx 文件，产品经理直接打开即可判断质量，CLI 返回成果清单即验收入口。

## 十、测试要求

**第一层 mock 测试（pytest，每次开发完必跑）**：
1. `compute_metrics`：用固定样例数据，断言总销售额/订单量/客单价/环比/Top5/渠道占比**数字精确等于手算值**。
2. `plot_chart`：三种图生成后文件存在、非空、格式为 png。
3. `read_file`：返回表结构 + 摘要而非整表；xlsx 与 csv 均可读；超大文件/非表格文件正确报错。
4. `write_file`：拒绝覆盖原始数据文件（原始文件保护红线）。
5. `loop` 端到端（mock 模型）：给定样例 xlsx，产出 report.md + 3 图 + data_summary.xlsx，且 report.md 中数字与 compute_metrics 一致。
6. `storage`：任务状态写盘后可恢复，续跑入口能读到已完成步骤。
7. `model` mock 提供商：返回非空总结，且不包含"编造"占位。

**第二层真实冒烟（验收前，Ollama 装好后）**：用一条真实销售 xlsx 跑完整链路，记录：总结可读性、有无编造、交付时长。D2/D3 验收标准在此轮由产品经理样例打分确定。

## 十二、风险与待确认项

| 风险 | 应对 |
| --- | --- |
| 真实 xlsx 列名五花八门，识别失败 | 内置别名映射 + 识别失败显式问"哪列是什么"，不瞎猜 |
| 未装 Ollama，写总结用 mock | 开发期 mock 推进，验收前装 Ollama；mock 结果如实标注，不冒充真实模型 |
| M1 无自动数字核对（verify_metrics 在 M2） | M1 数字正确性靠 pytest 精确断言 + 人工抽查；M2 上自动核对红线 |
| 需要产品经理决定的问题 | 无 |
