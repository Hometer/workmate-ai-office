# 阶段 3 v0.8 A 技术开发文档

日期：2026-10-02。依据：[PRD v0.8](../PRD/PRD-v0.8.md) F1—F5、现有技术适配声明、基线提交 `6df7ab8`。产品经理本轮已授权进入开发并要求先出文稿；本文件及真实验收方案先于代码修改创建。

## 1. 本阶段范围

实施检查/生成的数据版本一致、结构化总结和事实校验、全部产物口径一致、启动自检以及真实验收准备。保留现有 FastAPI、原生网页、轮询、文件存储、CLI、下载和历史任务。真实样表须经授权，模型须实际运行才能填写真实通过；无条件时完成可独立开展的开发并明确待验，不进入 B 的预设/复制功能。

## 2. 数据版本与兼容策略

- 新增受控表格快照：从原表一次性读取不超过 20 MB 的字节，计算 SHA-256 并从相同字节解析。检查统计与指纹一致，任务计算、独立核对和产物均使用这份快照；独立核对使用原算法及独立解析，不重新读取随时可能变化的源表。
- 快照字节只在本轮任务内存中持有，不额外留存完整原文。原表继续保留在授权目录；任务、检查凭据与依据持久化指纹、字段和确认信息。重启后中断任务按既有机制标为失败，可重新检查生成，不宣称自动断点续跑。
- `POST /api/v1/inspect` 请求保持 `{file, field_mapping?}`；响应保留原字段并增加 `confirmation_id`。随机凭据及文件路径、指纹、字段映射、时间持久化在已忽略的 `.workmate` 状态目录，日志不输出凭据或原始内容。
- 新网页提交 `{file, instruction, amount_mode, field_mapping, report_week, compare_week, complete, unit, confirmation_id}`。后端检查凭据存在且属于同一文件、映射一致，并以当前字节验证指纹；无效返回 `CONFIRMATION_INVALID`，文件已变返回 `SOURCE_CHANGED`，均为 HTTP 400 统一错误，不启动任务。
- 保持旧 v1 请求及 CLI 调用兼容：未传凭据时在提交时同步读取并检查当前输入，建立新的持久化凭据，将该请求视为“现在使用当前数据及所传业务参数”，返回 `confirmation_mode: compatibility_inspection`。它不能宣称复用了网页旧检查；已有检查记录与当前文件版本冲突时要求重新检查。新网页始终携带凭据。缺失/伪造凭据不能绕过数据解析、字段及业务校验。
- 创建任务时冻结快照、映射和业务参数，立即保存 running 状态及确认记录再提交后台线程，避免刚创建就查询不到。任务内再次校验映射，依据记录实际快照指纹和确认方式；源表随后变化时此次任务保持原已确认版本，下次任务重新检查。
- 历史 Task/依据增加可选字段，默认值兼容旧任务。新增接口字段均为加法，不改变既有错误结构或删除旧接口。

## 3. 结构化总结与确定性校验

模型职责为从已核对事实中选择最多三条重要结论，正文由确定性代码依据事实渲染，防止自由文本夹带不受支持的数字或因果。保留用户可读的简短中文总结，不在产品流程展示内部 JSON。

内部模型契约：`{"statements":[{"fact_id":"total_sales","value":600}]}`。`statements` 至少一条、最多三条；单条只允许 `fact_id/value/direction`，禁止额外自由文本字段。事实必须存在且已核对；value 必须等于该事实的规范显示值（金额两位小数、百分比为事实卡百分数、列表/字典逐项一致）。direction 可选且只用于环比，必须为 increase/decrease/flat 并与事实正负一致。

- 解析接受标准 JSON 或完整 JSON 代码围栏，不从任意散文中提取片段。Pydantic 校验类型、条数、字段，后端再校验可用事实、引用、值和方向；重复事实、未知 ID、错指标、小整数造假、无依据原因均拒绝。
- 指标标签、单位、统计范围和方向从已冻结事实读取；Top5 等名称中的数字不被误作金额。规范显示的四舍五入由事实卡决定，不采用宽泛“任意已知数值”匹配。
- 总结最长 200 字；超长、格式或事实不合格最多三次尝试，仍失败交付确定性摘要并标注降级。初始化、连接、超时与返回异常均兜底，不能让 SDK 初始化失败破坏数据成果。
- mock 适配同一结构，任务/结果/报告明确标为演示；不作为真实模型证据。持久化 provider、model、attempts、first_pass、validation_status、fallback_reason、elapsed_ms，日志仅记状态，不存模型原文。

## 4. 口径与单位贯穿所有产物

构造一份本次任务口径元数据供报告、汇总表、图表和页面使用：范围、金额口径、单位及来源、报告/对比周、核对状态、人工完整性确认、比较限制和总结身份。

- 图表标题/图注显示按周或全表范围；金额轴写明单位，渠道占比图也注明来源金额单位及限制。所有适用图使用同一元数据。
- 汇总表保留原工作表，关键指标增加单位和范围列，另加“口径与限制”表；不删除现有指标和下载。
- 正文添加统计范围、单位/来源、确认与限制；Top5 金额和降级摘要带单位。全表汇总不出现周报比较措辞。
- 页面分别展示数字核对、单位确认、人工数据完整性、模型/降级身份；历史没有新字段时显示“历史任务未记录”，不补造已通过状态。
- 币种为空/无效时不视为可靠声明，多币种保留阻断，不换汇。

## 5. 启动自检接口与网页

新增 `GET /api/v1/diagnostics`，返回 `{status, model_mode, model_name, checks:[{code,status,message,steps}]}`。检查数据目录可读/可上传、成果目录可写、本地模型服务及指定模型是否存在。目录测试用临时文件并及时清理，不改业务文件；Ollama 查询仅本机地址、短超时、禁止重定向，不发送业务输入。

mock 模式明确标为演示且真实模型待验；不能自动切模式。真实 Ollama 不在线、缺少模型或目录不可写时提供“去哪、做什么、看到什么算对”的指导；重新检查按钮重新获取状态。健康接口原结构保留。既有任务不依赖实时模型可用，历史和下载继续可访问。

当前环境若无 Ollama 或真实样表，不擅自把开发样例标为真实。安装/下载指导和实际设备验证记录在真实验收方案；不购买资源、不切云端、不升级核心依赖。

## 7. 风险与恢复

开发中补充（先记录再实施）：读取字节前后核对同一打开文件的状态，检测读取途中变动；绘图加进程内锁，避免既有两线程后台同时使用 matplotlib 全局状态混淆产物。图表底部同时保留统计范围、金额口径、单位与适用限制，完整性提示不等同于计算校验。仅接收明确识别的常见币种，其他声明由用户确认；空币种不伪装可靠识别。

模型输入中的商品/渠道名称统一替换为匿名标签，字段名改为业务角色，模型校验使用匿名事实，正文仍从本地可信原事实渲染；个人信息不进入模型输入。汇总表用户文本按纯文本保存，防止单位或维度名称被解释为 Excel 公式，数值保持原类型。

Ollama 请求明确指定 JSON 输出及非流式返回，验证 `done=true` 和文本内容类型，不把未完成响应当作成功。[官方 chat 契约](https://docs.ollama.com/api/chat)和[模型列表契约](https://docs.ollama.com/api/tags)已核对；实际模型质量仍待安装与业务样表验收。

后台已接收快照与确认后，源文件被外部删除或替换不改变该任务的输入；使用确认记录中的已授权路径及快照，后续新任务仍须重新检查当前源文件。检查记录内部结构损坏时拒绝放行，不默认为无检查记录。

浏览器实测补充（先记录再修改）：部分旧缓存仍复用旧样式，导致新增环境自检未采用新样式。为 HTML 引用的 CSS/JS 及 API 模块补充本阶段版本参数，沿用 no-cache 重验证；用户普通打开新版页面即可获取一致资源，不清除浏览器其他缓存。

启动补充：成果目录连状态目录也无法创建时，网页服务无法启动。CLI 的 serve/run/resume 初始化纳入统一异常处理，返回可读目录/状态错误而非堆栈；用户可先运行 diagnose 核对并按 README 恢复，不依赖一个无法启动的网页。

结构化输出可能提高真实模型重试/降级比例，须记录首轮和最终合规率，基于真实结果调提示与解析，不能放松事实底线。快照最多 20 MB、后台并发沿用两线程；内存占用与实际耗时在真实设备记录。新增凭据状态文件须原子写入并兼容重启，损坏时返回可操作错误，不能静默信任旧检查。

回退限于本轮代码，保留用户数据、历史成果、现有测试及隐私约定。阶段内发现调整时先补充本文件再实施。

收尾边界补充（先记录再实施）：模型 JSON 的极大整数与过深嵌套按非法输出处理，继续有限重试和降级，不能导致整个任务失败。非有限销售额（Infinity 等）在数据检查中记为无效，计算及独立核对拒绝；独立数值比较只接受有限值，防止聚合溢出被误判为一致。
