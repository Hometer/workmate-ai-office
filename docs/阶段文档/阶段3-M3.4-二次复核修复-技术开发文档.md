# 阶段 3 第 4 子阶段技术开发文档｜二次复核缺口修复

> 配套文档：PRD v0.6、`docs/evidence/项目复核-2026-09-29-二次/复核结果.md`。
> 本阶段修复二次复核发现的 6 个 P0、3 个 P1、1 个 P2，不新增业务范围。真实模型/真实样表/样例打分放最后。

## 一、阶段目标

堵住二次复核发现的遗漏，使"成功生成"真正满足 PRD v0.6 的验收要求。

## 二、缺口与修复方案

| # | 级别 | 缺口 | 修复 |
| --- | --- | --- | --- |
| 1 | P0 | 全表异常金额可绕过（报告/对比周之外的坏金额未阻断） | loop 在读表后先对**全表**销售额做空/非法值检查并阻断，再做周过滤 |
| 2 | P0 | 未确认完整仍输出变化事实 | 仅当 `complete.report` 且 `complete.compare` 都为真时才生成 `change_facts`，否则为空 |
| 3 | P0 | B 口径跨更早周订单漏检 | B 模式检测**任意自然周跨周**订单，跨周则周金额归属不清，不出环比并提示 |
| 4 | P0 | 模型结论卡片引用未校验 | 总结含数字时必须含事实卡编号引用（`[xxx]`），否则重试→降级 |
| 5 | P0 | 单一外币仍写成"元" | 识别币种列单一值：CNY/人民币→"元"，否则用该币种（如 USD）作单位；无币种列默认"元"并注明 |
| 6 | P0 | 错误响应泄露原始单元格 | `BAD_SALES_VALUE` 等错误不再附带原始值，只给数量 |
| 7 | P1 | 空金额网页放行到下一步 | 前端 `remainingBlockers` 增加"销售额空值"阻断 |
| 8 | P1 | 未选报告周却出周报与环比 | 有日期列但未选报告周 → 视为"销售数据汇总"（无环比、无周范围） |
| 9 | P1 | 参数校验错误格式不统一 | 增加 `RequestValidationError` 处理器，422 也返回 `{"error":{"code","message"}}` |
| 10 | P2 | 生成后历史列表不即时刷新 | 任务完成/失败后前端调用 `loadHistory()` 刷新 |

## 三、实现要点

- **#1**：新增 `compute.check_sales_full(df, mapping)`（复用空/非法判定），loop 在 `read_file` 后立即调用。
- **#2**：`change_facts = build_change_facts(...) if (complete or {}).get("report") and (complete or {}).get("compare") else []`。
- **#3**：`_b_cross_week` 改为 `_b_multi_week(full_df, mapping)`：任一订单在 >1 个自然周出现即返回 True。
- **#4**：`_summarize` 中：`has_digit = re.search(r"\d", text)`，`has_cite = re.search(r"\[[a-z_]+\]", text)`；`has_digit and not has_cite` → 重试。
- **#5**：`inspect.detect_currency_unit(df)` 返回单一币种值；`facts.build_facts` 与 `report_templates.render_report` 增加 `unit` 参数；`analysis_basis.json` 记录 `unit`。
- **#6**：`_to_numeric_sales`/`_to_numeric_independent` 错误信息去掉 `examples`。
- **#8**：loop 中 `is_summary_mode = (not mapping.get("date")) or (mapping.get("date") and report_monday is None)`；汇总模式强制 `mom_growth=None`，标题"销售数据汇总"。
- **#9**：`api.py` 加 `RequestValidationError` 处理器。
- **#10**：`app.js` 的 `pollTask` 完成分支后调用 `loadHistory()`。

## 四、测试要求（pytest，新增/修改）

1. #1：报告周外有一行坏金额 → 任务失败 `BAD_SALES_VALUE`。
2. #2：`complete` 为假 → `change_facts == []`。
3. #3：订单出现在第 1、3 周 → 无环比卡。
4. #4：注入"含数字无引用"总结 → 走降级/重试（单测 `_summarize` 或 safety）。
5. #5：单一 USD → 单位 "USD"，不写"元"。
6. #6：坏金额错误信息不含原始值。
7. #8：有日期未选周 → 标题"销售数据汇总"、无环比。
8. #9：缺 amount_mode 返回 422 且 body 含 `{"error":{"code":...}}`。
9. 既有 71 条测试保持通过。
