## 三、实现方案

### 1. 独立数字校验（`tools/verify.py` 重写）
- 不再调用 `compute.compute_all`，改为 `_independent_recompute(df, mapping)`：
  - 总销售额：Python 原生 `sum()` 逐值累加（区别于 pandas `.sum()`）。
  - 订单量：Python `set()` 去重计数（区别于 `.nunique()`）。
  - 客单价：独立重算的总销售额 ÷ 去重订单量。
  - 环比：手写按 ISO 周字典累加（区别于 `.groupby()`）。
  - Top5 / 渠道占比：手写字典累加 + 排序（区别于 `.nlargest()` / `.groupby()`）。
- 校验失败即任务失败（`VERIFY_FAILED`），行为不变。

### 2. 异常销售额报错（`tools/compute.py`）
- `compute_all` 里把销售额转数值后，检测"原本非空但无法解析"的单元格；存在则抛 `BAD_SALES_VALUE`，附数量与最多 3 个示例值，提示清理后重试。
- 空单元格（NaN/空白）不报错、不计入求和（语义正确）。
- 销售额列无任何有效数值时同样报错。
- `verify.py` 用同样规则做独立校验。

### 3. 运行中断恢复（`storage.py` + 启动入口）
- `Storage.recover_interrupted()`：把 tasks.json 中 `status=running` 的任务改为 `failed`，`result` 写 `{"error":{"code":"INTERRUPTED","message":"服务中断，任务未完成，可重新生成。"}}`。
- 调用点：`create_app()`（服务启动时，尚无任何任务线程）与 `cli.main()`（CLI 每次运行前），均在创建新任务之前执行，避免误伤正在运行的任务。

### 4. 格式统一（`tools/files.py` + 前端）
- `ALLOWED_EXT` 改为 `{".xlsx", ".csv"}`，移除 `.xls`。
- `index.html` 上传 `accept` 改为 `.xlsx,.csv`。
- 错误文案已是"仅支持 xlsx/csv"，无需改。

### 5. 历史任务输入同步（`static/app.js`）
- `loadTask()` 拿到任务后，把 `input_file` 的 basename 同步到文件下拉（若存在于列表），并把指令框同步为该任务的指令。

### 6. 图片加载失败提示（`static/app.js`）
- 图表 `<img>` 加 `error` 监听，加载失败时替换为"图片加载失败：文件名"的明确提示。

## 四、测试要求（pytest，新增）

1. **独立校验**：monkeypatch `compute.compute_all` 返回错误值，`verify.verify_metrics` 仍能检测出不一致（证明校验不依赖主计算函数）。
2. **异常销售额**：销售额列含 "abc" → 抛 `BAD_SALES_VALUE`；纯空单元格不报错、正常求和。
3. **中断恢复**：写入一个 `running` 任务 → `recover_interrupted()` 后变为 `failed` 且 error.code=INTERRUPTED；`done` 任务不受影响。
4. **格式**：`.xls` 上传/读取被拒绝（`UNSUPPORTED_FILE`）。
5. 既有 44 条测试全数保持通过。

## 五、验收清单（产品经理照着做）

- [ ] 用一张含"无法解析"销售额单元格的样表 → 页面/命令行明确报错，不交付错误总额
- [ ] 正常样表生成 → 报告、三张图、汇总表可打开，数字与原始表一致
- [ ] 服务运行中强杀进程 → 重启后历史任务里该任务显示"失败（服务中断，可重新生成）"，不再一直"进行中"
- [ ] 上传 `.xls` → 被拒绝（仅支持 xlsx/csv）
- [ ] 点历史任务 → 左侧文件下拉与指令框显示该任务当时用的文件和指令

## 六、风险与待确认项

| 风险 | 应对 |

| 强杀进程后恢复依赖下次启动 | 属预期行为（启动时恢复），符合 PRD v0.4 §5 |
| 需要产品经理决定的问题 | 无 |
