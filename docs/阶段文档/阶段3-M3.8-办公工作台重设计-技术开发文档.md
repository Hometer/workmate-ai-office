# 阶段3 M3.8｜办公工作台重设计

日期：2026-10-02。本文先于开发创建。依据产品经理此次“集聚现有功能、参考大厂办公产品、优化前端”的明确授权执行；v0.8 A 已确认的验收标准继续有效。

## 1. 前端技术适配声明

面向每周交销售周报的运营及小团队，主要终端为桌面浏览器，兼顾手机。继续使用 FastAPI 同源 API、原生 ES Modules、CSS 语义变量和系统中文字体。当前没有框架迁移需求，不引入 Next.js、商业字体、外部 CDN 或付费服务。沿用集中 API 客户端，任务及成果始终以持久化后端为准。

既有 JS 项目沿用静态资源交付，偏离手册默认 TypeScript / React 方案，避免本轮视觉重设计引发技术替换与迁移成本。开发前补充质量检查方案：四个浏览器模块统一 ESLint；新增业务转换模块、金额展示模块、API 客户端采用 JSDoc + TypeScript strict checkJs 检查；DOM 编排 app.js 沿用 JS，靠 Lint、接口回归与真实浏览器验证，本轮不宣称全量 TS 覆盖。增加原生静态资源构建脚本，只打包 HTML/CSS/JS 并验证模块引用、缓存版本和源码一致性，不编译框架。工具仅为开发依赖，固定版本和锁文件，不影响 Python 启动、运行时或数据格式。后续框架迁移需单独评估。本轮无影响范围的待确认业务决策。

## 3. 页面与现有功能整合

| 入口 | 功能与接口 |
| --- | --- |
| 工作台 | 一个集中的数据选择/上传入口、最近任务、进入制作步骤；GET data-files、tasks |
| 数据文件 | 查看真实已上传 CSV/XLSX 的名称、大小，选择文件立即检查，复用上传入口 |
| 历史成果 | 真实任务列表、按文件名搜索、状态过滤、打开成功或失败任务；GET tasks、tasks/{id} |
| 环境自检 | 独立、可读的检查页，重新检查和恢复建议；GET diagnostics |
| 制作周报 | 选择 → 检查字段/金额/单位 → 选周与完整性确认 → 真实任务执行 |
| 成果工作区 | 顶部范围、单位、总结身份；数字概览、正文、图表、数据依据四个页签；直接下载真实成果 |

报告页不长期占用左侧大块空表单。核心数字优先，完整事实、计算式和核对状态在依据页签回查；正文保留全部原始内容，图表与文件均来自现有任务。金额单位待确认、模型降级、对比不可用等提示不能被折叠隐藏。B 多商品不分摊等既有语义保留。

## 4. 状态与交互

| 模块 | 加载/空 | 等待/运行 | 成功 | 失败/恢复 |
| --- | --- | --- | --- | --- |
| 文件/历史 | 明确加载中；真实空列表才显示空态 | 上传禁重复，等待后端确认 | 显示真实列表，检查后刷新 | 错误与重试按钮，保留选项 |
| 检查步骤 | 数据摘要、字段标签关联控件 | 重检禁继续；金额口径由人选择 | 允许下一步；返回可修正 | 失败保留字段选择；修正后重检 |
| 生成 | 后端受理前显示提交 | 防重复，真实轮询，不伪造进度百分比 | 报告阅读与下载 | 失败原因、返回检查；连接失败提供恢复查询 |
| 报告 | 阅读加载态 | URL 持久任务 ID，刷新恢复 | 四页签，范围/单位/模型身份可见 | 某项失败独立提示，不能冒充完整加载 |

导航切换保留当前未提交表单；主动“新建周报”清空表单。正在运行的任务通过历史及任务 URL 找回，离开页面不会冒充取消任务。响应按任务 ID/页面请求版本防串台，轮询不重叠。页签使用 aria-selected、键盘箭头切换；移动导航使用真实按钮，不做假入口。

## 5. API 与安全

沿用 /api/v1/health、diagnostics、data-files、upload、inspect、tasks，以及 tasks/{id}/basis、facts、report、files/{name}。请求、响应、错误结构沿用已验收后端；错误统一 {error:{code,message}}，显示业务可恢复原因。GET / POST / 上传连接等待上限分别 15 / 30 / 60 秒，任务本身仍在后端独立执行；POST 超时不会自动重提，提示先查历史。创建任务保持原金额、日期、完整性、字段映射、confirmation_id 参数，不猜测默认口径。数据上传由后端校验真实类型和大小。同名文件不覆盖。

所有不可信文件名、文本、摘要和事实进行 HTML 转义；不把个人信息或密钥写入前端、URL、截图及日志。URL 仅记录任务 ID、页面和页签，不包含原文或凭证。单机单用户边界不变。

3. 390、768、1280、1440px 实际浏览器检查；手机导航和所有操作可触达，无页面横向溢出。检查键盘焦点、页签、图表加载错误和局部加载失败。
4. 原有 Python 与 Node 测试全部保留通过；新状态/筛选转换加入针对性 Node 测试；所有模块语法检查。实际重启服务验证任务及既有成果指纹不变。

## 7. 风险与回退

界面重排的主要风险是遗漏异常状态或旧任务。用当前成功/失败/降级/待确认任务及新生成覆盖；静态资源统一版本号防旧缓存。只改前端文件，不进行数据迁移。回退可恢复旧静态资源，原始输入与报告不变。手机实机与企业真实样表适用性仍为后续试用事项。
