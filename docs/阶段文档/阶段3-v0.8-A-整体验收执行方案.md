# v0.8 A 整体验收执行方案

日期：2026-10-02。产品经理要求代为验收 A，明确无数据时可生成或查找数据。本方案先于本轮验收执行及必要修复创建。

## 范围与结论口径

沿用 F1—F5、已有 172 项测试和本地 Ollama + qwen2.5:7b。选择可独立核算的合成销售样表，覆盖 10 个正常业务场景和独立异常样例，不冒充企业真实数据。真实业务试用另列待办。本轮可证明真实模型与合成输入的完整链路；产品经理评分与瑕疵容忍度需依据可读结果确认，执行者代评不记为产品经理已评分。

不开发 B，不购买资源，不切云端，不覆盖现有数据或成果。样表、独立基准、原始验收记录、模型与运行文件保存在被忽略的 `outputs/acceptance-v08-20261002/`。仓库证据仅含公开说明、合成截图、核对步骤和阶段闸门，不含命令输出或日志。

## 执行步骤

1. 核对实际设备、已有模型服务及容量。从 Ollama 官方发布下载可移除的本地运行程序，校验发布文件摘要；使用独立模型目录和仅本机服务，不改变项目 `.env`。模型 qwen2.5:7b 官方标识 Q4_K_M、约 4.7 GB，记录实际版本与模型摘要。
2. 生成 10 份小型 CSV/XLSX 样表，分别覆盖 A 周报增长/下降、B 整单去重、退款负数、字段别名、无订单号、单位待确认、对比无记录、B 多商品不分摊、全表汇总。每份记录显式业务含义和独立人工式基准；基准使用 Decimal 与普通集合/累加，禁止调用应用计算/核对函数生成预期答案。
3. 从检查、确认、提交到真实模型、生成、下载逐条运行，检查事实、报告、表格、图表、依据和原表指纹。保存总样例数、首轮合规、重试合规、降级、耗时及所有失败；不只展示成功项。
4. 补充无效金额、多币种、无日期周报、跨周 B、源表变化与凭据等负例。实际验证 Ollama 未启动、模型缺失、恢复连接和超时；目录不可写用受限权限的真实目录访问验证。故障不能冒充成功模型结果。
5. 使用 ego-browser 技能在桌面与 390px 检查代表性正常、错误、恢复、下载和自检，实际停止/重启验收服务后核对历史、成果及确认持久化；检查原有成果未变。
6. 如发现问题，先在本方案追加原因与修复设计，再修改代码、增加相关回归、重新运行适用样例和完整检查。未关闭缺口如实列出。
7. 交付样例核对报告、四维代评分及推荐验收标准，更新 README、PRD、项目状态和闸门。真实模型未跑通不得宣布通过；产品经理未确认的评分不伪造为已定。

## 判定

硬性底线是数字/范围/单位与独立基准一致、总结无不受支持结论、原表未改、成果可打开、恢复和隐私要求满足。合成数据来自本轮授权，可作为工程验收输入；真实企业表兼容性仍需实际业务试用。

结论分开列出工程验收、真实本地模型链路、真实业务适用性和产品经理评分，按实际证据填写十项闸门。任何原 PRD 条件尚未满足时不将 A 原定整体闸门改为全部通过。

## 验收发现及修复设计（先记录再开发）

F4 页面渠道变化条目只显示数值，没有金额单位；负 delta 与“减少”组合成“减少 -125.5”，容易误读。总额、事实与依据计算正确，问题位于前端呈现。

新增纯格式化函数：从变化条目或总销售额事实取得单位，未记录时明确“单位待确认”；方向和幅度分别展示，下降采用正的变化幅度。由确定性代码依据 delta 正负生成方向，无效金额写待确认。用户文本继续 HTML 转义。兼容旧任务，不改写历史成果，不改模型契约。

为此次前端资源补充新的版本参数，增加 Node 原生回归覆盖 USD/元/待确认、下降/持平/无效值和文本安全边界；原有 Python 回归保留。使用一份另存的美元合成样表真实生成，浏览器复验变化条目的单位和方向，再交付最终证据与评分确认。

执行结果：Python 172/172、Node 6/6 通过，真实美元复验显示增加 425.5 USD、减少 125.5 USD；桌面/390px 复验无横向溢出。产品经理已明确回复“认可代评分与标准，按本轮范围验收 A”，确认授权合成数据替代本轮业务样表、全部 10 份代评分、D2/D3，企业真实样表试用另列后续。因此按此次已定范围填写 A 最终闸门，不冒充真实企业试用通过。详见最终验收报告。
