# 阶段 3 M3.7 技术开发文档

日期：2026-10-02。依据：PRD v0.7 F2/F4、2026-10-02 复核的 R10-1/R10-2、既有前端技术适配声明。本文件先于代码修改创建。产品经理已授权立即修复，无新增待确认业务决策。

## 目标与范围

当周金额无法可靠归属或字段选择无效时，系统明确拒绝产生可信报告，让用户知道如何修正。范围包括后端统一校验、网页可见错误与返回检查入口、针对性回归测试及证据。沿用 FastAPI、原生 JavaScript、本地单用户、A/B 金额口径和当前文件存储。不引入云资源、费用、新平台或数据迁移，不修改历史成果。

## 修复规则

### R10-1 跨周 B 口径

- 对全表的完整订单号按自然周建立归属集合，订单号清洗沿用 B 口径的去首尾空格逻辑。同一订单涉及多个自然周即归属不清。
- 若所选报告周包含归属不清的订单，在周切片、计算、核对、事实卡、模型总结和成果落盘之前返回 `ORDER_WEEK_AMBIGUOUS`。不能通过隐藏环比继续交付已核对周金额。
- 错误提示不包含原始订单号，说明“报告周包含跨周订单，金额归属不明确；请修正日期归属，或返回检查页将日期列设为不指定，改做全表汇总”。
- 同一订单在同一自然周的多个日期，不阻断周总额；B 全表汇总仍按订单去重，A 口径仍按行相加。
- 其他周的跨周订单不阻断所选报告周自身可靠的金额；沿用现有保守规则禁止跨周比较结论。若归属不清影响对比周，跳过该周计算与核对，不将其标为已核对。
- 异步生成失败继续持久化为 `failed`，保存统一错误码和提示；既有历史任务保持原样。

### R10-2 非法字段映射

- 建立共享的映射校验函数，允许的业务字段为 sales/date/product/channel/order；值须为当前文件中实际存在的列名，选填字段可为空或 null。
- 检查接口、创建任务接口及核心执行入口都使用该校验。直接调用 Loop 也不能绕过；任务创建后读取文件时再次校验，防止已失效的列进入计算。
- 映射非法返回 `FIELD_MAPPING_INVALID` 和通用提示，不在报错中回显请求值、列内容或堆栈。缺少销售额沿用当前可读检查阻断和 `COLUMN_UNKNOWN` 机制。
- 检查与创建任务接口返回 HTTP 400、`{"error":{"code":"FIELD_MAPPING_INVALID","message":"…"}}`；请求形状不合法仍由现有 HTTP 422 校验处理。创建任务前校验失败不提交后台任务。

## 网页处理

生成失败显示后端提示，保留回到检查流程的入口。字段重新检查时禁用继续入口；重新检查失败时保留已选字段，并在当前检查页显示错误，不能沿用上一次统计放行。沿用既有刷新和历史任务恢复，不增加自动修改源文件或自动选择金额口径的行为。

浏览器实测补充：同一本地地址重新启动服务后，浏览器仍可能复用旧 HTML/JS，导致后端已修复、页面仍使用旧失败提示。为保证修复可见，本轮补充静态资源 `Cache-Control: no-cache`，允许保留 ETag 缓存但每次重新验证。覆盖 HTML、JS 和 CSS 响应及 304 响应，不清理用户 Cookie 或浏览器全局缓存。已有页面在本轮验收时执行一次强制刷新，之后普通刷新即可重验证。该补充先记入本文件再修改代码。

## 验收标准

| 场景 | 必须观察到的结果 |
| --- | --- |
| B 同一订单跨两周或不相邻周，涉及所选报告周 | 明确失败，错误码为 ORDER_WEEK_AMBIGUOUS；无成果、无事实卡、无模型调用；失败状态重启可查 |
| B 跨周只影响对比周 | 报告周金额可交付，无环比/变化结论，对比周不标已核对 |
| B 跨周在所选两周之外 | 自身报告周金额仍可交付；保留既有比较限制 |
| B 同周多日期 / B 全表汇总 / A 跨周明细 | 原有适用行为保持可用，金额与独立核对一致 |
| 检查或创建任务传入不存在的任意映射列、非法值或未知业务字段 | 统一 400 错误结构，不泄露传入敏感字符串，不产生后台任务 |
| 直接调用 Loop 传非法映射 | 可读业务错误，失败状态落盘，无成果 |
| 前端字段重检失败 | 原选择仍在，错误在检查页可见，继续入口禁用；恢复有效映射后可继续 |
| 桌面和 390px 网页失败及正常生成 | 错误可读、可重新检查；正常报告、图表与下载可用，无横向溢出 |
| 服务重启 | 本轮失败与成功任务均可重新查询；已有成果和源文件不变 |

先增加或加强测试以复现两项缺口，随后实现修复，执行全量 pytest、两个 JavaScript 模块语法检查、依赖检查、差异格式检查及真实浏览器验收。原测试不删除；此前跨周测试从“只检查无环比”加强为“拒交归属不清的周金额”，这是修复行为所需的更严格标准。

真实 Ollama、真实业务样表及人工质量评分沿用 v0.8 待验安排。本阶段证据须明确 mock 身份，真实验证未通过时不宣布整体阶段质量验收完成。

## 风险与回退

此前跨周 B 任务可能显示成功；新生成会要求先修正归属。只改变存在歧义的新增任务，不删除或改写旧报告。若发现误阻断，优先通过同周/不相关周回归场景修正判定，不能降低跨周报告标准。回退只撤销本轮代码改动，不动用户数据和既有修改。
