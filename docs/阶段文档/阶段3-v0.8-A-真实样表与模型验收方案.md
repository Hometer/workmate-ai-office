# v0.8 A 真实样表与模型验收方案

日期：2026-10-02。本方案先于开发创建，初稿时真实模型、业务样表及评分均待验；同日后续已完成真实模型 + 授权合成样表验收，产品经理确认代评分及标准。企业真实业务试用另列后续，当前以最终报告为准。

## 样例来源与授权

准备 5—10 份产品经理授权的真实销售样表。执行者负责目录、匿名编号、运行和整理；产品经理负责业务口径判断及评分。现有 sample/开发文件不自动作为真实材料，未经授权不读取未知文件内容。

真实文件、基准和评分放在已忽略的 `outputs/.workmate/validation/`，样表可放授权 `data/`；不要提交 Git。证据截图仅在授权并脱敏后交付，业务名称和原始订单号不进入模型或日志。合成数据边界回归单独记录，不能填补真实样例数量。

## 每份样表确认卡

| 字段 | 填写要求 |
| --- | --- |
| 匿名编号、授权状态 | 用 V8-01 等编号，确认可本地处理与可交付材料边界。 |
| 金额含义 | 每行商品金额/重复整单金额；含税或未税、退款/负数如何解释。不确定则待确认。 |
| 范围及完整性 | 全表/报告周；前一自然周是否有记录、两周是否由用户确认完整。 |
| 单位与映射 | 货币单位来源；实际销售额、日期、订单、商品、渠道列。 |
| 独立人工答案 | 总额、行数、订单量、客单价、适用排名/占比/环比及不可用原因。独立于系统计算。 |

执行者整理可读卡片后逐份确认影响计算的口径，不一次抛出超过五个必须回答的问题。

## 实际模型准备与运行

沿用本地 Ollama、`qwen2.5:7b`，记录实际模型标签/版本和电脑环境。若本机未安装：执行者提供官方安装入口及逐步指导；安装 Ollama 后，在终端运行 `ollama pull qwen2.5:7b`，看到下载完成，再启动本地服务并在工作台点“重新检查环境”，指定模型显示可用才开始。模型下载可能数 GB，下载与首次启动耗时单独记录，不自动购买云资源。

每种总结契约及正常周报、全表汇总至少跑一条实际链路；适用 B 样例也独立核对。若模型不存在或无法运行，标“待验”，不能以 mock 或确定性降级摘要记通过。真实模型加合成输入可验证模型连接/契约，但须标“真实模型 + 合成输入”，不算真实业务样表验收。

记录实际模型身份、任务编号、数据版本、耗时、第一次输出结构是否合格、总尝试数、最终是否合格、降级原因与成果可打开情况。不记录模型原文或完整用户表；用状态和匿名编号描述失败。

实际关闭本地模型服务并查看提示，再恢复连接检查；超时/畸形返回等可用确定性故障回归补充，明确验证方式。单机本地模型无需云 Key，不因“无 Key”否定真实本地验证。

## 产品经理评分与标准冻结

生成 5—10 条真实结果后，执行者逐条展示数字依据和周报，不只展示成功项。四个维度各 1—3 分：结论正确、引用准确、依据易回查、表达适合交付。1 分需明显修改或不可用，2 分少量修改可用，3 分可直接用；另标不能接受项与原因。

硬性数字、隐私、原表只读与证据真实性不能以平均分抵消。D2/D3 的总通过条件及瑕疵容忍度在首次评分后由产品经理确认；不预设数值宣称通过。修复不能接受项后复验对应真实样例。
