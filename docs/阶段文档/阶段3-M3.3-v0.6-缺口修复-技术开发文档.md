# 阶段 3 第 3 子阶段技术开发文档｜v0.6 缺口修复

> 配套文档：PRD v0.6、《前端技术适配声明》、阶段3-M3.2 v0.5 P0 文档。
> 本阶段修复 PRD v0.6 §2.2 的 G1~G10 缺口，不新增业务范围。真实模型/真实样表/样例打分放最后。

## 一、阶段目标

让"成功生成"同时意味着：输入通过全表检查、金额与时间口径被后端确认、数字与结论有依据、桌面与 390px 移动端可用、刷新可找回任务。逐项关闭 G1~G10。

## 二、缺口与修复方案

| # | 缺口 | 修复 |
| --- | --- | --- |
| G1 | 空销售额时 inspect 返回 500（JSON 含 NaN） | inspect 所有返回值做 NaN/Infinity 清洗（→ null）；preview 值清洗；quality 计数为整数 |
| G2 | 无业务列时 preview 暴露 PII 原值 | preview 仅输出「已映射且非 PII」的列；映射失败时返回空预览 + 安全提示，不回退全列 |
| G3 | 绕过页面调接口不传口径也受理（默认 A） | `amount_mode` 必填且仅 A/B；后端 `loop.run` 再校验；CLI `run` 增加必填 `--amount-mode` |
| G4 | 空金额/坏日期被静默排除，排除清单为空 | 空金额与无法解析金额都阻断；周模式下日期有空/坏值阻断（提示修正或切"销售数据汇总"）；`analysis_basis.exclusions` 记录任何排除 |
| G5 | 390px 横向溢出 1045px，图表撑破 | CSS：`#result img` 限宽；`.mapping/.facts/.chart-grid` 移动端单列 |
| G6 | 网页无历史任务入口 | 前端加"历史任务"列表，可打开完成/失败任务，刷新后按 URL `?task=` 找回 |
| G7 | 选周页不显示两周覆盖，切周沿用旧确认 | inspect 返回每自然周的覆盖统计；前端展示；切换报告周时清空两周完整性确认 |
| G8 | 接受任意对比周/完整性；B 跨周订单漏检 | 后端由报告周推导对比周并校验相邻；B 模式检测跨周订单，归属不明确时不出环比并提示 |
| G9 | 总结未强制 200 字/引用；对比周未独立核对却标"已核对" | 总结长度收紧到 ≤200 字；对比周指标也独立核对，双周都通过才标"已核对" |
| G10 | 币种未检查；报告未完整展示不可用原因 | 检测到币种列且多币种时阻断；报告/事实卡展示不可用原因（已有部分，补齐） |

## 三、实现要点

- **G1/G2**：`inspect.py` 增加 `_clean(v)`（NaN/Inf → None）；`preview()` 白名单为「映射值 ∩ 非 PII」，空则返回 `[]`。
- **G3**：`api.TaskRequest.amount_mode` 用 `Literal["A","B"]`（必填）；`loop.run(amount_mode=None)` 时若缺省/非法抛 `AMOUNT_MODE_REQUIRED`；`cli run` 加 `--amount-mode {A,B}`（required）。
- **G4**：`compute._to_numeric_sales` 对空单元格也抛 `BAD_SALES_VALUE`（附空值数量）；`loop` 周模式下先检查全表日期空/坏值，有则抛 `BAD_DATE_VALUE`。
- **G5**：`styles.css` 移动端单列 + `#result img { max-width:100%; height:auto }`。
- **G6**：`app.js` 复用 v0.4 的历史列表逻辑，`index.html` 加历史区。
- **G7**：`inspect.py` 返回 `week_stats`（monday、有效行、有记录天数、日期空/错误数）；前端展示；`renderWeek()` 重建时清空 `state.complete`。
- **G8**：`loop` 用 `weeks.previous_week(report_monday)` 推导对比周，客户端传值不一致则忽略并记 warning；B 模式用 `amounts.order_level` 检测跨周订单，跨周则 `mom=None` 且加 warning。
- **G9**：`loop._summarize` 长度阈值 200；`loop` 对 `compare_metrics` 也跑 `verify.verify_metrics`，双周都通过 `verify_ok=True` 才传给 `facts.build_facts`。
- **G10**：`inspect`/`compute` 检测"币种/currency"列多值则抛 `MULTI_CURRENCY`；`report_templates` 增加"不可用原因"段落（口径提示已存在，补齐各图不可用原因）。

## 四、测试要求（pytest，新增/修改）

1. G1：含 NaN 的表 inspect 返回可序列化 JSON（不含 NaN）。
2. G2：仅有"客户姓名、备注"的表，preview 不含姓名原值。
3. G3：不传 amount_mode / 传 "C" → 后端拒绝；CLI 缺 --amount-mode 报错。
4. G4：空金额阻断；周模式坏日期阻断；exclusions 记录排除。
5. G8：传不相邻对比周被忽略/拒绝；B 跨周订单不出环比。
6. G9：总结 >200 字降级；对比周校验失败即任务失败。
7. G10：多币种阻断。
8. 既有 65 条测试更新后全数通过。
