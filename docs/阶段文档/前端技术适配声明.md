# 前端技术适配声明

> 项目：WorkMate（M3 产品化）｜日期：2026-09-28｜依据：PRD v0.3、《通用前端技术栈手册》V1.0、《技术适配声明》。

## 1. 项目判断
- 产品类型：本地优先的 AI 办公助理（数据分析/生成类，单场景销售数据周报）。
- 主要用户：每周交数据周报的运营/销售/个体店主/小团队负责人（**单机单用户**，D5 已定）。
- 主要终端：桌面 Web（本地 localhost），兼顾移动浏览器。
- 新项目或已有项目：已有项目（后端 workmate 包已完成 M1+M2）。
- 本阶段业务目标：把已验证的后端引擎做成"浏览器里选表/传表 → 点按钮 → 看周报"的本地网页界面。

## 2. 输入资料
- PRD：已读取（v0.3）。
- 后端手册：已读取。
- 接口文档：后端此前为 CLI/包，本阶段新建 FastAPI 接口（自研，草案）。
- 设计稿：无（按中性默认方案先做一版代表页，再请产品经理反馈）。
- 现有代码：有（workmate 包：loop + 7 工具 + verify/safety + 持久化 + 日志）。

## 3. 技术选择
- **框架与版本：不用 Next.js**。前端为一个很小的嵌入式静态页（HTML + ES 模块 JS + CSS），由 FastAPI 直接挂载。
  - 原因：单机单用户、单页、属"表单提交 + 后台生成 + 下载结果"类产品（通用手册 §5 明确此类型用单个 HTML 放 static/、原生 JS + fetch）；Next.js SSR 无增益。
- 样式与组件策略：原生 CSS + 语义变量（中性方案），不引入组件库。
- 数据请求与状态策略：`fetch` 集中封装在 `api` 模块；后端任务状态映射为前端统一状态。
- 流式通信策略：无（本地任务为短请求，用"提交 + 轮询状态"）。
- 表单方案：原生表单 + 基础校验。
- 测试方案：后端 pytest（FastAPI TestClient 测接口）+ 真实浏览器验收（桌面与移动截图）。
- 部署环境：本地 uvicorn 服务（端口可配，默认 8000）。

## 4. Agent 状态
- 后端状态 → 前端统一状态映射：
  - `created` → `idle`
  - `running` → `running`
  - `done` → `succeeded`
  - `failed` → `failed`
- 等待用户确认方式：本产品无（确定性流水线，落盘无需确认，M1/M2 已定）。
- 取消、重试、断线恢复方式：刷新后按 `task_id` 查询后端真实状态（tasks.json 持久化），不靠前端内存。
- 任务 ID 和恢复入口：URL 查询参数 `?task=<id>` + 历史任务列表。

## 5. 页面与产物
- 核心页面：单页工作台（文件选择/上传 + 指令输入 + 生成按钮 + 结果区 + 历史任务列表）。
- 核心业务闭环：选表 → 输入指令 → 生成 → 看 report.md + 3 张图 + 下载汇总表 → 刷新可恢复。
- 产物类型和预览方式：markdown 文本（直接渲染为 HTML）、png 图片（`<img>` 预览）、xlsx 文件（下载）。
- 响应式目标：1280px / 768px / 390px。

## 6. 偏离本手册的地方
- 偏离项：不用 Next.js / React / Tailwind / TypeScript，改用 FastAPI 静态页 + 原生 JS。
- 原因：见 §3（很小的嵌入式页面，通用手册 §5 与前端手册 §5.1 均允许）。
- 影响：无 Node 构建步骤，`lint/typecheck/build` 项以"API pytest + 真实浏览器验收"替代；若未来对外 Web 上线，再评估迁移 Next.js。

## 7. 待确认事项
无。D5（单机单用户，无需登录）、D2/D3（验收标准）均不影响本阶段前端范围。
