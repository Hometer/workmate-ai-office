## 功能与恢复检查

- 四个导航入口可用；文件列表显示真实文件，点击即检查；重复同名上传沿用后端拒绝覆盖。
- 历史按文件名及状态筛选；无匹配项与加载失败分开显示，失败时有刷新入口。
- 返回上一步保留输入；在导航之间切换保留未提交表单。换文件清除旧单位、周次及完整性确认，金额口径重新由人确认。检查页显示当前文件名，上传/检查时避免源文件切换与重复操作，控件在结束后恢复。补充浏览器响应中数据指纹变化的明确故障注入，验证旧单位和两周完整性确认被清除；原表未修改，没有生成模拟模型结果。
- 历史失败任务显示业务原因，返回对应文件重新检查；不打开另一份无关数据。字段重检失败禁继续，恢复有效字段才可继续，见 [重检阻断](字段重检阻断-1440.png)。
- 延迟旧任务依据响应后立即切换另一份真实报告，旧响应释放后仍显示新任务，历史切换未串台。
- 对原图加载进行故障注入，提示错误且保留下载，点“重新加载图表”恢复全部原图和当前图表页签，见 [图表故障](图表加载故障注入-1440.png)。
- 页签支持键盘方向键、Home/End，当前页签可通过 URL 刷新恢复；浏览器前进/后退可以回到对应工作区和任务。
- 单位待确认、降级摘要、无有效比较等状态保留可见提示，旧报告身份未记录与新报告真实校验通过明确区分。
- 依据加载失败使用明确标注的浏览器故障注入，单独显示待读取，恢复请求后重读原任务成功；这项不冒充真实模型测试。
- 实际停止 8766 服务，自检和历史显示连接错误；恢复服务后刷新和报告可用，未重复创建任务，8000/8765 及模型服务未停。
- 实际重启前 28 个任务和 129 份本地文件均恢复且不变。本轮之前 118 份原表/成果指纹不变；确认记录随新检查正常追加。原始样表和旧成果没有被覆盖。
- 390、768、1280、1440px 首页与成果无页面横向溢出；手机字段、周次、图表、依据及异常均可触达，主要步骤操作高度 44px。此项为实际浏览器尺寸检查，手机实机另验。

工程检查：Python 172/172，Node 15/15；ESLint、三个核心模块 strict checkJs 通过，四个 JS 模块语法及六个资源静态构建通过。前端 DOM 编排保留原生 JS，未宣称全量 TypeScript。构建只包含 HTML/CSS/JS，不包含配置、私有输入或依赖。

## 产品经理照着看

1. 打开 [新工作台](http://127.0.0.1:8766/)。看到浅色侧栏、上传/文件选择、最近任务，算首页正确。可以先看整体颜色、字体和密度。
2. 点“数据文件”，选择 M38-sales-acceptance.csv。看到字段与金额口径，选择 A，点“继续选择周次”；选择 2026-09-28 并按样例事实勾选两周完整，点“生成销售周报”。生成真实模型可能需要几十秒，等待最终状态；刷新可继续查看。已有验证结果可直接打开 [本轮周报](http://127.0.0.1:8766/?task=b22948985b2d)，无需再生成。
3. 在成果页依次点“数字概览 / 报告正文 / 销售图表 / 数据依据”。数字与上表一致，顶部下载能得到文件，算成果正确。依据页有来源、公式和单位，不需要阅读技术日志。
4. 点“历史成果”，输入 M38-sales，并点“已完成”。看到对应报告且可打开，算搜索正确。点“未成功”可查看已有失败记录及原因，点“返回重新检查”回到对应数据。
5. 点右上角环境图标或侧栏“环境自检”，点“重新检查”。看到本地环境可用与三个检查项，算当前环境正确。不要停其他服务或删除原表来试验故障。
6. 把窗口缩窄或查看手机截图。导航、控件、正文与下载可触达，没有左右撑出屏幕，算宽度检查正确。
