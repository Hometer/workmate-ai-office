# M3.7 修复验证结果

日期：2026-10-02。先交付《阶段3-M3.7 复核缺口修复技术开发文档》，再增加回归断言、开发和验证。本轮关闭 R10-1、R10-2 的代码缺口；整体真实模型及业务质量验收仍待 v0.8，不宣布全阶段完成。

## 修复后的行为

| 问题 | 修复前 | 修复后 |
| --- | --- | --- |
| B 口径同一订单跨自然周，影响报告周 | 仍交付已核对周金额，仅隐藏环比 | 在计算与生成成果前失败，提示修正日期归属或改做全表汇总；不产生事实卡、报告或模型调用 |
| 跨周只影响对比周 | 对比周按切片计算且标记已核对 | 可靠的报告周可交付，对比周不计算、不核对，依据和页面解释限制 |
| 无效列名、字段类型或未知业务字段 | 检查接口普通 500；创建任务后才失败 | 检查和创建任务接口返回统一 HTTP 400 / FIELD_MAPPING_INVALID；核心 Loop 同样校验 |
| 字段重新检查失败 | 错误可能写到隐藏区域，旧结果仍能放行 | 当前检查页显示错误，保留选择，禁用继续；换回有效字段后恢复 |
| 更新后页面缓存 | 可能继续加载旧 HTML/JS | HTML、JS、CSS 及 304 响应要求重新验证缓存 |

同周多个日期的 B 订单、B 全表去重汇总和 A 每行金额仍可运行；归属不清仅发生在其他周时，不阻断所选报告周本身可靠的金额。跨周比较继续沿用现有保守限制。

## 验证与证据

自动测试 **114/114 通过**：保留原有 82 个测试，将其中两项跨周测试从“只验证无环比”加强为“拒交不可信周金额”，新增 32 项参数化场景。开发前先运行针对性回归复现旧问题，未删除测试、降低标准或隐藏异常。模型相关测试使用 mock；这些通过数不代表真实模型质量。

新增场景覆盖不相邻周、去首尾空格后的订单号、同周多日期、与选周无关的跨周订单、对比周不可核对、两类接口的全部五种映射字段、非法映射类型/未知字段、空选填字段、Loop 直调、失败持久化，以及静态资源缓存重验证。跨周拒交场景还断言不调用模型、不生成成果、不修改输入文件。

两个 JavaScript 模块语法检查、依赖一致性检查和差异格式检查通过。没有引入新的前端构建或类型检查配置，继续沿用已批准的原生 JavaScript 适配。Starlette/httpx 保留一条原有弃用提示，没有升级依赖来消除提示。

浏览器直接操作本地服务验证了以下流程：

1. 跨周样表选 B 和 2026-09-28 报告周，出现明确错误和“返回重新检查”，结果区无事实卡或已核对金额。
2. 点击返回，重新检查同一虚构文件，把日期列设为“不指定”，按 B 口径得到全表销售额 100、明细 2 行、订单 1 单，未重复计算为 200。
3. 在专用虚构样表中模拟检查后列被外部移除，再从页面改选该列，实际后端返回 400，错误在当前页显示且继续按钮禁用。原选择未被自动改写；恢复测试样表并换回有效字段后可以继续。这是受控修改测试夹具，原始业务数据未参与或被修改。
4. 正常 A 口径样表选周，仍得到销售额 600 元、4 条明细、3 单、客单价 200 元、环比 50%。报告、汇总表与网页一致，3 张图加载成功，浏览器下载与成果原文件一致。
5. 对比周含跨周订单的任务，页面显示“未计算或核对该周金额”，报告周总额仍为 50，依据的 compare 核对标志为 false。

390、768、1280、1440px 正常结果页均没有页面级横向溢出；桌面与 390px 错误页可读，按钮可操作。移动宽度是浏览器模拟，未做手机实机验收。检查期间未观察到 JavaScript 异常；专门触发的无效映射请求返回 400 属于预期错误。

已实际停止并重新启动服务：本轮成功、失败、全表汇总和受限对比任务均可恢复；失败任务仍显示 ORDER_WEEK_AMBIGUOUS，且没有成果。修复前 16 个成果文件及本轮 13 个成果文件指纹不变，正常输入样表也未改变。专用字段变更夹具已恢复原内容。

历史任务保留当时的状态和成果，包括修复前产生的跨周错误结果；它们没有被后台重写。本轮新生成才适用新的拦截规则，验收请使用下面明确给出的任务链接。
